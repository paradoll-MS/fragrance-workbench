# 端到端流程与模型节点 v3

## 两个生产阶段

1. 解析：每次上传执行格式解析；图片/音频走视觉或 ASR，扫描 PDF 逐页识别；之后初步分类。原件、全文、页段定位、人工备注均保留。
2. 理解：用户点击开始自动生成后，一个全景理解节点产出项目简报、可追溯故事、全部子项目、各子项目简报及客户额外要求、品类 K 码、ABC 推断、资料重新标注与需求覆盖。

一个逻辑理解阶段通常一次调用；标签缺少语义依据或跨轮气味结构与有效要求冲突时，允许一次有界的内部契约校验调用。标签校验只补依据；跨轮校验只修正冲突的气味字段及当前有效气味要求，并保留旧值审计。两者都不能改项目客户信息、任务路由、基准号或原文。有效完整输出不触发第二次调用。失败输出保留供追查。

生产理解 prompt：`prompts/understand_project.md`。解析初标 prompt：`prompts/classify_artifact.md`。项目问答是独立按需节点，不参与生产流水线。

## 执行机制

POST `/api/projects/{id}/generate` 立即返回 run id，后台线程执行。GET `/api/projects/{id}/generation` 读取持久状态。刷新浏览器仍可恢复；服务重启将中断任务标为失败。一个项目只允许一个活跃 run。

先存完整输入快照和指纹，模型成功后校验所有资料覆盖、真实标签、品类归属、原文引用和输出结构，再一次事务提交。生成期间人工编辑或任务推进使指纹变化时，本次结果不覆盖当前项目。

全文超过容量直接报告，不静默截断。输出达到模型长度上限报告失败。`understanding_max_tokens` 可在本地配置中设置，默认 48000。模型不可用不会用少量关键词拆分伪装成全景理解。

## 推断与事实

A 识别想要的味道/香材/香韵；B 理解感受与产品语境风格；C 在该内部品类预设标签中推断商业定位和体验偏好。每个标签保留 reason、confidence、source_refs。否定项另列，未知本体记缺口，不自动创建无香精覆盖的硬标签。

## 完整上下文与引用校验

原始全文完整发送；重复的派生段落以全文定位代替，重复的工单简报以子简报引用代替，避免相同内容成倍占用上下文。完整输入快照仍独立保存。所有所选ABC必须有语义依据；跨品类C剔除并显示审查说明。引用按原文锚定；空白或非连续拼接可校正定位并记录校对方式，数字、否定与关键化学/方向变化拒绝。
