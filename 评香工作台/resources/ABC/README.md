# ABC 选香模块接手

选香工作台帮助评香把真实需求变成可调整的筛选条件和标签，快速得到一组知道为何入选的香精。评香可以修改条件、选出香精，也可以把闻香后确认的标签修订留给以后使用。

## 目录

- [docs](docs) 放人可读的结果表、复核清单、清洗说明和历史报告。第一轮表是全库视图，第二轮表是较早的 838 款增量快照。
- [scripts](scripts) 放离线清洗脚本。根目录的两份工作簿分别是 V2 字典和冷启动底稿，供脚本读取。
- [output](output) 放机器可读的清洗交付及批次统计。[调用说明](docs/README_调用说明.md) 记录字段和来源。
- [_work](_work) 放复跑所需的输入、批次结果和历史证据。工作簿的临时文本快照也在这里生成。

## 开工顺序

1. 对齐 [wanted](../../评香工作流设计/wanted.txt) 的请求和返回值。三个模式共用一次选香流程。价格、品类和目录条件由评香或上游明确给出，香气需求映射到待确认的 ABC 标签。精确找产品继续沿用 wanted 的身份检索分支。
2. 先用手工标签打通工作台。让评香能调整硬性条件和偏好、看直接命中与 C→AB 关联、选定香精并返回 wanted。直接标签执行硬筛，关联用于排序。三个模式共用评分函数，权重在真实案例里试调。
3. 接入一次需求映射。简单且能唯一对应字典的输入先试直接解析，复杂需求再走模型。默认识别正向偏好，客户明确提出排除时才生成排除条件。分别测量常规短输入和品牌描述。
4. 保存需求修订、香精标签修订和实际选香记录。评香确认的资产标签优先于后续自动补标，历史证据继续可追溯。

首批验收用短香气词、香型加价格、香水香型洗衣液和品牌 brief。先验证筛选、结果解释和改标签是否符合评香的工作方式，再确定权重、映射补分和界面细节。使用正式数据前，复核冲突编码按源行归属、历史品类的候选身份及报价口径。复跑第二轮前确认工单库路径。
