# Recommendation ／ ABC 选香
当前实现和实查结果见 [第二轮选香试跑](../../评香工作台/research/recommendation-推荐试跑.md)。

关键要求补充：
- 首先要有负向的提取字段（减分但是不打死）
- 其次在推荐的列表里面展示的时候要写简要提示，就是可能不符合的问题（超价/主韵不符）或推荐主要理由（加分最大的标签）



## 1. 三种模式

1. **recommend_simple／常规推荐**。顶部是应用品类、价格、品牌目录、大牌仿香、新品、爆品。下一行是香气词和已映射的 ABC。确认条件后显示排序候选；可选定、指定原香改香或调整条件。仅目录需求直接浏览。
2. **recommend_brand／品牌推荐**。先看定位、人群、场景、风格和排斥项，再看可修改的 ABC 与硬筛。显示每个候选的直接命中、C→AB 理由、未匹配意图。目标位按需选择库香、创香、改香。解析不到标签时保留原文，可以手选标签或进入目录浏览。
3. **with_sample／对香**。样品和到达状态放在顶部；从查编号、标签辅助、直接开发三条路选一条。标签搜索输入来自评香对实物或现有描述的判断，由 F08 转换。F09 分值用于找候选，感官结论由评香另填。相似度可以空，也可选接近即可、尽量一致或补自定义原文。直接开发记录跳过检索。
4. **find_product／精确找香**独立。显示身份、版本、精确关系和待核线索，空结果可启动仿香。价格与品类冲突单列，界面保留身份判断；条件符合的精确关系才可直接选。产品风格参考走品牌推荐。

## 2. 硬筛和放宽

- 应用品类从 ABC V2 的 CAT_01—CAT_12 中选，多选 OR。已确认应用品类默认硬筛；缺品类可先做 AB 或手动浏览，以「应用待确认」提示，C 暂空。评香可显式关闭品类硬筛或显示 `category_candidates`，候选归类有提示。历史使用不直接变成已确认应用品类。
- 客户明确上下限默认严格执行，闭区间。仅写目标价且未明确上限时默认作参考排序项和展示项，手动开启可填写上下限或目标价上浮比例（试跑默认 20%，仅在显式开启弹性时使用）。无金额、币种或计价单位无法换算时，保留价格原文并标待确认。硬筛已开启时未知价单列待查，不能算通过；导入价在模拟中台按数据种类明确显示。只在同币种、同单位、可比价格口径内比较；负数、零、区间文本或无法判定的数据进待查。
- 品牌树取每个分支上最深的选择，不同分支 OR。新、爆、已确认大牌关系及各额外目录维度分别 AND。只有客户明示或评香开启时使用相应维度，未核验大牌候选仅可单列显示。无筛选要求时，unknown 标志不扣分。
- V3 的 A1 OR、无 A1 时 A2/A3 OR 保留为「锁定主香型」的可见建议。明确必需的香气由评香确认后可启用默认 OR 组；宽泛概念和样品辅助检索默认留作偏好。同组可切为 all；不同组 AND。关闭 A1 不会自行开启 A23。C/B 默认是偏好，支持手工锁定具体标签。必需/排除只看香精自身标签，缺直接标签不能靠 C→AB 得分通过。硬排除会排除直接命中的香精；该维度完全无标签的条目单列待闻，界面提示标签缺失。客户明确排除默认建议锁定，评香确认；暂缓某硬性条件需记录原因。安全、法规或成分限制交检查环节。
- 应用条件、价格、目录、硬标签和本方向明确拒绝项逐项执行。保存每个条件的顺序剩余量，以及仅移除该条件重算时多出的候选量。空池显示有影响的条件，评香点选放宽；待定价格、身份冲突和历史品类候选各自有解释。

## 3. F09 首版计分配置

三个 ABC 模式共用 `abc-v1`。初值沿 V3 的当前代码及修正说明，ABC 工作簿提供标签与关联边。ABC 的《各种模式.md》为空，现有资料未指定独立的模式权重。后续调权重发布新配置并保留旧快照。

1. 从当前需求的正向目标标签取去重集合 A（A1、A2、A3 合计）、B、C。在各自维度比较，C 需同应用品类。软目标与硬组可包含同一个标签，已经用于硬筛的具体 ID 在直接得分排除。
2. 候选自身直接命中每个 A 加 1，B 加 1，C 加 3。人工从 C 闸门下钻并明确勾选合法叶；模型在只有闸门依据时将路径记作待确认。C 实际参与计算的都是当前查询明确保存的叶。
3. 仅从需求侧已选正向 C 取字典的 C→A1/A2/A3/B 边。同一 AB 若由多个 C 关联，贡献一次 +1，记录所有来源 C。只比候选自身已有的 AB。直接分和关联分独立，硬筛 AB 在关联轮可计 1 分；入负向组的 AB 不计加分。条件细化不自动扩入未选的 C 叶。关联只用于排序和解释。
4. 总分 = A 直接分 + B 直接分 + C 直接分 + 映射分。实例以工作簿 C_114「小众沙龙香水风格」和 C_130「文化叙事 / 年代氛围叙事」为目标，两者都关联鸢尾。候选有 C_114 与鸢尾，鸢尾又是硬筛项时，得分为 3 + 1 = 4。解释列展示两个来源 C，鸢尾的直接分为 0。若候选只有自己某个 C 隐含鸢尾但缺鸢尾原生标签，映射分为 0。
5. 有可计标签时，总分降序、C 直接分降序，再看可比已知价、价格升序、确切已知的历史用样次数降序、catalog_key 升序。启用参考目标价且未硬筛时，同分组内先按已知价格对目标的绝对差升序，再走价格规则。异币种/价口径不可比时同排未知项；可按价格另行排序。无可评分信号时进入目录浏览，隐藏相似分，沿相同价格和稳定次序。零分候选折叠至「其他候选」；缺标签和已知未命中分别展示。首屏 30 条，可分页；不存在隐藏的自动选香。
6. 每个结果保留 fragrance_id、catalog_key、原生 ABC、direct_A/B/C、mapped_score、total_score?、direct_hits[]、mapped_hits[]（ab_id、via_demand_c_ids[]）、unmatched[]、missing_dimensions[]、quote、条件状态及用样计数口径。分数是同一查询内排序依据。来源和历史置信度不改变有效 ABC 标签的权重。已拒绝标签排除，人工删除以覆盖层生效。

## 4. 两条数据回流

- 「编辑香精标签」用 F11 写 `catalog_fragrances` 当前投影和 `catalog_changes`。手改名称或应用品类也需要 manual 记录；改应用品类后移出不再适用的 C，并保留变更历史。联机报价、正式编号、配方版本由中台接口负责。重新导库后已确认的人工增加与删除仍有效。结果页面可刷新，旧快照可按原版本追溯。
- 「编辑需求标签/筛选」用 F08 写 `search_queries` 与 `targeting_feedback`。项目原始意图另用 F04 保存 BriefRevision。查询修订即时应用当前轮；反馈保存模型原提案、人工修改、来源和版本，只作人工复盘与后续提示词优化资料。已选和已派发的历史用旧快照。
- 选香决定、已闻过、明确排除和实际寄出分别保存。候选排名不直接进入历史选香。项目拒绝项可按轮继承，默认记录方向和来源。

## 对 1. 三种模式的修改建议

1. 三种 mode 共用一套 ABC 需求映射、硬筛、评分和结果编辑机制，仅输入语境、默认权重和界面展示重点不同。不分别维护三套 Prompt 和评分函数。
2. recommend_brand 中的排斥项不需要作为默认展示区域，仅在客户明确提出排斥需求时显示。LLM 不得根据正向偏好自动生成反向限制。
3. with_sample 的标签默认作为偏好而非硬性要求。评香可以根据对香判断手动锁定核心香韵。匹配分仅用于寻找候选，不代表实际感官相似度。
4. 简单需求应走最短路径。仅目录需求、人工直接选择标签、能够无歧义映射的独立香气词，可以跳过 LLM，直接进入筛选及评分。其他需求原则上只进行一次 LLM 映射。
5. find_product 保持独立，不调用 ABC 评分。明确产品身份与该产品风格的相似性推荐是两个不同任务。

## 对 2. 硬筛和放宽的修改建议

1. 应用品类硬筛默认使用 searchable_category_ids，即原库归类、人工确认品类及具有合理历史推荐或实际应用依据的 category_candidates 的有效并集。界面区分品类依据，支持切换为仅检索已确认品类。历史应用证据不代表应用测试通过。

2. V3 的 A1 OR、无 A1 时 A2/A3 OR 仅保留为人工「锁定主香型」的快捷操作，不作为自动生成硬筛条件的规则。LLM 根据需求语义直接建议哪些标签属于硬性要求、哪些属于偏好，以及组内 ALL/ANY 关系。例如：

   - 「柠檬香型」：A1 柠檬可建议锁定。
   - 「薰衣草或玫瑰」：A1 薰衣草、玫瑰组成 ANY 组。
   - 「玫瑰搭配乌木」：可建议组成 ALL 组。
   - 「清新的木质香」：A2 木质可建议锁定，B 清新感为偏好。
   - 「高级极简的空间香氛」：以 B/C 偏好为主，不强行产生硬性标签。

   LLM 主动联想得到的标签默认只能作为偏好。所有硬性建议均可由评香直接调整。

3. 大牌仿香筛选提供「包含高可信候选」选项。现阶段库内大量仿香关系尚未人工确认，应允许这些候选参与推荐，但明确展示身份状态；不能作为 find_product 的精确身份命中。

4. 多品类 OR 检索时，每个品类拥有独立的需求 C 和香精 C。不得将不同品类的 C 合并后执行硬筛和评分。AB 可以共用；C 硬性条件只在其所属品类分支生效。

5. 否定排除属于低频功能。仅在客户明确提出排斥某种香气时生成排除建议，不根据天然、高级、清新等正向描述自动生成反向条件。第一版不额外引入软性负向扣分机制。

6. 价格、新品、爆品、品牌、仿香关系等目录条件与 ABC 香气匹配分离。它们用于硬筛、展示和独立排序，不默认混入 ABC 得分。

7. 保留现有筛选诊断机制。调整任何硬筛条件、ABC 标签及组内关系后，由程序即时重新筛选和评分，不重复调用 LLM。

## 3. Matching & Ranking／ABC 匹配与排序

### 3.1 执行逻辑

承接第2节的筛选结果，对通过全部硬筛条件的香精执行 ABC 匹配评分。

评分由确定性函数完成，不调用 LLM。三个 mode 共用评分函数，通过 ScoringConfig 区分权重及关联映射系数。

评分包含五种匹配关系：

- A direct match／A1、A2、A3 直接匹配。
- B direct match／B 直接匹配。
- C direct match／C 直接匹配。
- Fragrance C → Query AB／香精 C 的关联映射支持需求 AB。
- Query C → Fragrance AB／需求 C 的关联映射支持香精 AB。

C→AB 映射仅表示市场选香中的关联偏好，不代表两者语义等价，不参与硬筛，不写回需求标签或香精标签。

### 3.2 ScoringConfig／默认评分配置

with_sample／对香：

- A1：30
- A2：25
- A3：25
- B：15
- C：5
- α：0.15
- β：0.20

recommend_simple／常规推荐：

- A1：25
- A2：25
- A3：20
- B：15
- C：15
- α：0.25
- β：0.30

recommend_brand／品牌推荐：

- A1：10
- A2：15
- A3：15
- B：30
- C：30
- α：0.35
- β：0.50

其中 α 为香精 C 支持需求 AB 的映射系数，β 为需求 C 支持香精 AB 的映射系数。

另设参数 saturation_count，初始值为 2，表示需求 C 通过多少个不同的 AB 关联命中达到映射补分上限。

以上为初始试跑配置，统一存储并提供管理入口，不写死在评分函数中。后续根据实际选香测试调整。

### 3.3 Direct Match／直接匹配

对于每个参与评分的需求标签 t：

- 香精自身具有该标签：match(t) = 1。
- 香精自身没有该标签：match(t) = 0。

A1、A2、A3、B 分别独立匹配。

C 仅在当前应用品类下匹配。

已用于硬筛的标签默认不重复参与偏好评分，因为所有通过硬筛的候选均已满足相应条件。

当前有效标签均可参与匹配，包括合理的冷启动推断和历史工单补标，不因证据来源不同而在第一版设置额外评分系数。

### 3.4 Cross Match／双向关联匹配

#### 方向一：香精 C 支持需求 AB

当需求 AB 标签 t 未直接命中时，检查香精在当前品类下的全部有效 C 标签所对应的 AB 关联。

- 直接命中：match(t) = 1。
- 未直接命中，但香精 C 的关联映射包含 t：match(t) = α。
- 均未命中：match(t) = 0。

多个香精 C 同时支持一个需求 AB 时，仅计算一次。

#### 方向二：需求 C 支持香精 AB

对于需求 C 标签 c：

1. 如果香精直接具有该 C，match(c) = 1。
2. 否则获取该 C 对应的 A1/A2/A3/B 关联集合。
3. 将关联集合与香精自身的有效 AB 标签取交集并去重，得到命中数量 n。
4. 计算：

   match(c) = β × min(n / saturation_count, 1)

例如 recommend_brand 中 β = 0.50，saturation_count = 2：

- 无关联命中：0。
- 一个 AB 关联命中：0.25。
- 两个及以上 AB 关联命中：0.50。
- C 直接命中：1。

C 对应的 AB 是多个可能的香气方向，不是必须全部满足的条件。因此不使用命中数量除以 C 的全部映射数量的方式评分。

#### 关联计分约束

- 直接命中优先，不重复获得同一标签的关联补分。
- 已参与直接 AB 评分的相同香精 AB 标签，默认不再用于需求 C 的额外关联补分。
- 同一个 AB 对同一个 C 的支持只计算一次。
- 双向映射仅进行一轮，不递归扩展。
- 不调用其他应用品类的 C 及其映射。

### 3.5 Score／综合匹配分

沿用第2节中需求标签的组内逻辑。

- ALL 组：取组内各标签匹配值的平均。
- ANY 组：取组内各标签匹配值的最大值。
- 单个标签视为只有一个成员的标签组。

分别对 A1、A2、A3、B、C 各层级参与评分的偏好标签组取平均，得到：

S_A1、S_A2、S_A3、S_B、S_C。

每个层级分值介于 0 和 1 之间。

综合匹配分：

Score = 100 × Σ(w_i × S_i) / Σ(w_i)

其中：

- w_i 为当前 mode 下相应层级的权重。
- 求和仅包括本次需求中存在有效偏好标签的层级。
- 未提出需求的层级不参与分母，不因缺少需求而降低总分。
- 香精没有相应标签时，该需求的匹配值为 0，但不解释为香精必然不具有该属性。
- 不对香精的全部标签数量评分，不因无关标签过多而加分或扣分。

例如常规推荐仅有 A2 和 B 偏好，则实际参与评分的权重为 25 和 15，而不是全部100。

当不存在任何偏好标签时，Score = null，直接展示满足硬筛条件的目录候选。

### 3.6 Multi-category／多品类评分

多品类 OR 检索时，分别建立各品类下的有效需求及候选分支。

每个分支：

1. 执行该品类对应的硬筛条件。
2. 使用共用 AB 和该品类独立的 C 进行评分。
3. 记录该品类下的完整 ScoreDetail。

同一香精在多个品类分支中均满足条件时，默认取最高匹配分作为其综合排序分，并展示最佳匹配品类。其他品类的匹配结果仍可查看。

如果某个品类分支没有任何偏好标签，其匹配分为空，不参与最高分比较。

如果客户要求同一香精同时适配多个品类，则不属于默认 OR 语义，应由上游明确指定或分别组织选香任务。

### 3.7 Ranking／排序

默认排序：

1. ABC 综合匹配分降序。
2. 同分时，直接匹配的加权贡献降序。
3. 仍然同分时，按稳定的香精资产 ID 排序。

提供独立的人工排序选项：

- 匹配分优先。
- 价格升序或降序。
- 目标价格接近程度。
- 新品优先。
- 爆品优先。

价格排序仅比较符合第2节价格口径要求的数据，未知价单列或置后。

目录属性不默认参与 ABC 综合分。没有香气偏好的纯目录需求可以直接浏览及排序。

### 3.8 ScoreDetail／评分输出

每个候选应返回：

- fragrance_asset_id：稳定的香精资产身份。
- fragrance_id、fragrance_name：香精编号及名称。
- matched_category_id：本次最佳匹配的应用品类。
- category_evidence：品类依据。
- score：综合匹配分，允许为空。
- level_scores：A1/A2/A3/B/C 各层级分值。
- direct_hits：直接命中的需求标签及贡献。
- cross_hits：关联命中的需求标签、对应 C→AB 路径及贡献。
- unmatched_preferences：未命中的偏好标签。
- passed_constraints：满足的硬筛条件。
- catalog_attributes：价格、价格段、新品、爆品、品牌及产品关系。

结果界面应明确区分直接命中和关联支持。综合匹配分表示现有标签数据对客户需求的支持程度，不表示实际闻香相似度、应用合格概率或法规通过情况。

### 3.9 Recalculate／重新计算

以下操作均直接触发程序重新筛选或评分，不调用 LLM：

- 修改需求 ABC 标签。
- 切换硬性要求与偏好。
- 修改 ALL/ANY 关系。
- 修改价格、目录及品类筛选条件。
- 修改三个 mode 的评分参数。
- 修改香精自身的 ABC 标签。
- 修改 C→AB 关联映射。

仅在需要重新理解自然语言需求，或重新映射新的品类语境时调用 LLM。

保留本次查询版本、评分配置版本、字典版本及最终选香记录，以便后续复现和调整排序算法。
