# 输入端资料类型与读取方式（LLM 参考）

更新：2026-10-28  
用途：给后续整理项目资料的 LLM 一个固定的“先判断资料是什么，再决定它能证明什么”的参考。  
这份文档不定义具体项目结论，也不要求每次把所有资料找齐。

---

## 一、可直接放进 system prompt 的版本

```text
你是香精项目资料整理助手。你的任务不是替客户做决定，而是把项目输入整理成
“可追溯的事实、明确的目标、存在的约束、尚未解决的问题”。

在阅读任何资料前，先做三件事：
1. 识别资料类型、作者/说话人、时间、版本、受众和用途；
2. 判断它能提供哪类信息，不能证明什么；
3. 把“客户原话、会议决定、销售转述、内部推测、待办计划”分开。

规则：
- 不把资料里没有写的内容补成事实；缺失就标 unknown / absent。
- 不把“需求目标”当成“已经实现的结果”，不把“候选/推荐”当成“客户已确认”。
- 不把品牌名、产品名、图片、包装文字直接拆成香精原料或配方。
- 法规、价格、性能、稳定性等结论必须带市场、品类、版本、单位或测试条件；**价格原文没有单位时，默认按元/公斤（香精单价）理解**，上下文明确是成品/零售/样品价时另记并待确认。
- 遇到冲突，保留双方原文和来源，不静默合并，最后列出待确认问题。
- 每条关键信息尽量带：来源类型、原文摘录、说话人/作者、时间、置信度。
```

## 二、总原则

1. **资料不是同等事实。**  
   客户原始 brief/邮件/聊天原话，通常高于会议纪要，高于销售转述，高于二手总结；但“原始”不等于“正确”，仍要看时间、版本和说话人。

2. **先识别任务，再抽取字段。**  
   同一句“要一个高级感”，在选香、仿香、概念创香、法规核查里含义不同。先判断这是 T01–T14 中的哪类任务，再决定要关注什么。

3. **区分五种句子。**
   - 事实：已经发生、可核验（“6 月 20 日寄了 50g”）。
   - 决定：会议/邮件中明确拍板（“确定用 A 方案”）。
   - 目标/约束：希望达到或不能违反（“要 24h 留香”“成本 80 以内”）。
   - 偏好/意见：个人或单方倾向（“我觉得偏甜”）。
   - 推测/待办：销售判断、计划、下一步（“应该会喜欢”“下周寄样”）。

4. **任何数字都要带口径。**  
   价格有单位按单位；**原文没有单位的报价数字，默认按元/公斤（香精单价）理解**。若上下文明确是成品价、终端零售价或样品金额，不要套默认，另记并待确认。留香是 24h 还是“第二天闻得到”；温度是高温 45℃ 还是室温；法规是哪个市场、哪个品类、哪个版本。

5. **任何“对标”都要问目的。**  
   是仿香、同款指认、近似参考、风格参考、竞品分析，还是只想借一个名字？目的不同，能迁移的标签和结论完全不同。

6. **缺失也是信息。**  
   没有寄样记录、没有价格、没有市场、没有稳定性条件，都应该成为“待确认项”，而不是用常识补齐。

## 三、资料类型卡

### A. 客户 brief / 需求表 / RFQ / 开发通知书

| 项 | 说明 |
|---|---|
| 典型形式 | Word/PDF/Excel brief、邮件正文、客户系统导出的需求表、附件中的产品说明 |
| 能提供 | 产品品类、目标市场、目标受众、价格目标、对标产品、香型方向、法规/宣称要求、交付时间、数量、包装/剂型 |
| 不能证明 | 客户最终会选哪支、目标能否实现、价格是否可接受、法规是否已核查 |
| 可信度 | 高，但要看版本日期、收件人、是否被后续邮件/会议修改 |
| 重点抽取 | 产品身份、用途/品类、市场、受众、价格及单位、对标及目的、法规/宣称、性能/稳定性、交付物、时间、数量、包装 |
| 常见坑 | 把“目标价”当报价；把“参考某产品”当仿香；把旧版 brief 当最新；把客户愿望当已确认结果；忽略附件中的表格/图片 |

**读取动作**：先找“这是给谁、做什么产品、卖到哪里、什么时候要”；再找“必须”和“希望”的区分；最后记录 brief 的版本/日期和附件清单。

---

### B. 初次会议纪要 / 拜访记录 / 电话或会议转录

| 项 | 说明 |
|---|---|
| 典型形式 | 会议纪要、拜访记录、电话记录、录音转录、项目启动会 PPT |
| 能提供 | 项目背景、决策人、优先级、未写入 brief 的约束、双方对“高级感/大牌感”的解释、下一步动作 |
| 不能证明 | 具体配方、最终价格、法规结论；会议上的“可以”不一定是客户书面确认 |
| 可信度 | 中高；取决于记录人、是否会后确认、是否有未记录的私下沟通 |
| 重点抽取 | 决策人/角色、项目阶段、优先级、明确决定、待办、争议点、对brief 的修改 |
| 常见坑 | 把记录人的总结当客户原话；把“讨论过”当“决定”；漏掉会后的微信/邮件变更；把多个方案混成一个 |

**读取动作**：把“决定/待办/未决”分开；每个决定尽量找到后续书面确认；没有确认的，标为“会议口头”。

---

### C. 对标产品链接 / 图片 / 包装 / 截图

| 项 | 说明 |
|---|---|
| 典型形式 | 品牌官网链接、电商商品页、香水资料库、产品图片、包装正面/背面、社媒截图 |
| 能提供 | 品牌/产品身份、版本/浓度、香调表、产品类型、包装宣称、目标受众、价格带、市场 |
| 不能证明 | 香精配方、实际原料、客户要“仿”还是“参考”、图片闻起来是什么 |
| 可信度 | 身份信息高（官网/品牌页）；香调表中等；图片/社媒低到中；链接可能失效或版本混淆 |
| 重点抽取 | 品牌、产品名、版本/浓度、产品类型、香调表、宣称、受众、价格、市场、链接/截图时间 |
| 常见坑 | 同名不同版本（EDP/EDT/Extrait/年限量）；把“像某香”当同款；把图片包装文字当配方；把品牌名拆成原料；把“对标”默认成仿香 |

**读取动作**：先锁定“品牌+产品+版本+类型”，再记录“客户给的是链接、图片还是口头提到”；最后单独问“对标目的”。

---

### D. 销售—客户微信 / 聊天记录 / 语音转文字

| 项 | 说明 |
|---|---|
| 典型形式 | 微信文字、截图、语音转录、群聊、转发消息 |
| 能提供 | 实时反馈、价格/交期谈判、寄样/收样、包装/标签、临时变更、客户语气和优先级 |
| 不能证明 | 完整技术结论、正式确认、全部上下文；截图可能缺前因后果，转发可能失真 |
| 可信度 | 中；客户原话较高，销售转述较低；语音转录有错字/漏字 |
| 重点抽取 | 说话人、时间、客户原话、涉及的产品/样品、数量/价格/交期、寄样状态、明确决定、待办 |
| 常见坑 | 把销售的话当客户的话；把“收到”当“认可”；把“再看看”当拒绝；截图没有时间；群聊里多人意见混在一起；语音转写错词 |

**读取动作**：按时间线排列；每条消息标“客户/销售/其他”；只把客户明确说的当客户事实；销售总结另标“转述”。

---

### E. 销售输入 / 文本框粘贴 / 口头转述

| 项 | 说明 |
|---|---|
| 典型形式 | CRM/工单文本框、销售在群里发的一段话、电话后销售补记 |
| 能提供 | 客户背景、真实优先级、竞品/价格压力、内部判断、下一步动作 |
| 不能证明 | 客户原话、技术可行性、最终选择；经常是二次总结 |
| 可信度 | 中低到中；越接近客户原话越高，越像“销售自己的判断”越低 |
| 重点抽取 | 谁说的、是客户意思还是销售判断、涉及产品/市场/价格/时间、明确待办 |
| 常见坑 | 把销售判断写成客户需求；把“客户可能喜欢”写成“客户要”；漏掉“这是我自己猜的”；把多个客户混在一起 |

**读取动作**：先问“这是客户原话、销售转述，还是销售判断”；无法区分时标“二手/待核”。

---

### F. 项目/工单系统记录

| 项 | 说明 |
|---|---|
| 典型形式 | 项目表、工单、样品行、需求/评香/调香备注、状态字段 |
| 能提供 | 项目编号、客户、品类、历史用样、角色、修改目标、反馈、寄样/打样记录 |
| 不能证明 | 字段名等于实际含义；历史推荐等于客户确认；状态“结束”等于客户选样 |
| 可信度 | 中高，但字段可能错填、备注可能是协调日志、状态可能不同步 |
| 重点抽取 | 项目/工单、样品行、实际用样 vs 正文提及、角色、需求、修改、反馈、时间 |
| 常见坑 | 把“推荐/候选”当“已选中”；把“项目结束”当“样品达标”；把字段名当事实；把同一香精多次打样合并成一次 |

**读取动作**：把“实际用样、正文提及、仅品牌提及、无号样品”分开；每个结论保留工单/样品 ID。

---

### G. 样品与寄样记录

| 项 | 说明 |
|---|---|
| 典型形式 | 寄样单、快递单、样品登记、库位/灌样记录、销售自提记录 |
| 能提供 | 是否寄、寄了什么、数量、收件人、时间、快递/自提、补寄 |
| 不能证明 | 客户是否收到、是否试用、是否认可、是否选中 |
| 可信度 | 高（物流事实）；但“填报日期”不一定是实际发生日 |
| 重点抽取 | 样品/内部号、数量/规格、收件人/地址、寄出/到达、快递号、自提/邮寄、补寄原因 |
| 常见坑 | 把“安排寄”当“已寄”；把“已寄”当“已收到”；把“收到”当“认可”；填报日期 vs 实际日期 |

**读取动作**：状态分成“计划—已寄—已达—已试用—有反馈—已确认”，不要跳步。

---

### H. 报价 / 成本 / 商务表

| 项 | 说明 |
|---|---|
| 典型形式 | 报价单、成本表、价格邮件、Excel、聊天中的数字 |
| 能提供 | 目标价、报价、样品金额、币种、单位、税率、起订量、交期 |
| 不能证明 | 最终成交价、客户接受、成本可达成 |
| 可信度 | 高（数字本身）；但口径容易混 |
| 重点抽取 | 金额、币种、单位（元/kg、元/样品）、含税/未税、目标/报价/成交、日期、数量；**无单位报价默认元/kg** |
| 常见坑 | 样品金额当公斤价；目标价当报价；人民币/美元混用；区间价取中值；“100–200”被写成 150；把成品/零售价套成元/kg |

**读取动作**：任何价格都写“谁给的、什么口径、什么时间、什么数量条件”。

---

### I. 法规 / 合规 / 检测 / 稳定性 / 表现力报告

| 项 | 说明 |
|---|---|
| 典型形式 | IFRA 证书/声明、SDS、COA、过敏原表、法规评估、稳定性报告、性能测试报告 |
| 能提供 | 某版本/某用途/某市场下的合规或测试结论、测试条件、限值 |
| 不能证明 | 其它市场/品类/版本也适用；报告存在不等于产品已注册/已批准 |
| 可信度 | 高，但必须看版本、日期、市场、品类、测试条件、样品批次 |
| 重点抽取 | 法规/标准、市场、品类、香精版本/批次、用量、测试条件、结论、有效期 |
| 常见坑 | 把 IFRA 当全球法律；把 SDS 当合规批准；把一次稳定性当所有包装；把“符合”当“客户已接受” |

**读取动作**：先问“这份报告对哪个版本、哪个用途、哪个市场有效”；再问“测试条件是什么”。

---

### J. 内部评香 / 调香 / 应用记录

| 项 | 说明 |
|---|---|
| 典型形式 | 评香笔记、调香修改记录、应用打样记录、内部邮件 |
| 能提供 | 气味描述、修改目标、基料/剂量/工艺、失败原因、版本关系 |
| 不能证明 | 客户偏好、市场接受、法规合规 |
| 可信度 | 中高；取决于记录人、是否有对照、是否是个人判断 |
| 重点抽取 | 样品/版本、评香人、参照、阶段、基料/剂量、修改目标、结果 |
| 常见坑 | 把评香师个人意见当客户意见；把“原液好”当“应用好”；把修改目标倒灌给旧版本 |

---

### K. 邮件 / 附件 / 图片 / 音频等零散材料

| 项 | 说明 |
|---|---|
| 典型形式 | 邮件正文、附件 PDF/Excel、产品图、标签图、录音、截图 |
| 能提供 | 补充上下文、正式确认、附件中的表格/参数 |
| 不能证明 | 附件正文一定被读过；图片一定是最新版本 |
| 可信度 | 看来源和日期；附件可能比正文新，也可能旧 |
| 重点抽取 | 发件人/收件人、日期、附件名、附件中的关键表、版本 |
| 常见坑 | 只看正文不看附件；附件是旧版；图片文字 OCR 错；邮件转发丢失上下文 |

## 五、一句话记忆

**先问“这是什么资料、谁说的、什么时候、对哪个产品/市场”，再问“它能证明什么”；不能证明的，放到待确认，不要补成事实。**
