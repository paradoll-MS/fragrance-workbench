# 端到端流程与 LLM 节点

更新：2026-10-28  
用途：让评香/开发知道每个环节由谁做、LLM 具体做什么、读什么 prompt、参考哪些文档、输出什么、哪里必须人工确认。

## 0. 总图

```text
文件接收/解析（规则 + 视觉/ASR）
  → N01 资料分类与标注（LLM）
  → N02 项目简报抽取（LLM + 规则）
  → N03 故事索引（规则 + 可选 LLM 摘要）
  → N04 子项目拆分（LLM + 规则）
  → N05 品类映射（规则 + LLM 兜底）
  → N06 任务类型/路由（LLM + 规则）
      ├─ find_product → 精确匹配 → 有/无
      ├─ match_sample → 评香对香
      ├─ recommend_simple → 硬筛 → 排序
      ├─ recommend_brand → N07 目标 C（可选/多选）→ 硬筛（不含 C）→ C×3 + AB×1
      ├─ modify → 改香 brief
      └─ create → 创香 brief
  → N08 候选解释（可选 LLM）
  → N09 部门任务生成（规则 + LLM）
  → N10 终点检查（规则）
  → N11 问答（LLM + 检索）
```

## 1. 节点总表

| 节点 | 触发 | 做什么 | Prompt | 主要参考 | 输出 | 人工确认 | 失败/降级 |
|---|---|---|---|---|---|---|---|
| 文件接收/解析 | 上传/粘贴/链接 | 提取文字、页码/段落/时间戳；图片/音频转文字 | 无（规则）；视觉/ASR 模型 | 输入端资料类型 | 文本、定位、原件 | 解析失败人工补摘录 | 保留原件，标待补 |
| N01 资料分类与标注 | 解析完成 | 判断资料是什么、角色、备注 | `classify_artifact.md` | 输入端资料类型、重点关注信息 | 类型/角色/备注/置信度 | 评香可改 | 低置信给“其他/待确认” |
| N02 项目简报抽取 | 资料齐/手动触发 | 六组字段 + 证据 + 缺项 | `extract_brief.md` | 重点关注信息、价格默认、品类映射 | brief JSON | 评香逐项改/确认 | 缺字段留空，不编 |
| N03 故事索引 | 简报保存后 | 时间线/原文/决策可检索 | 规则；可选 `story_summary.md` | 输入资料类型 | story sections + FTS | 一般不需要 | 原文仍可查 |
| N04 子项目拆分 | 简报确认后 | 按香型+任务类型拆子项目 | `split_subprojects.md` | Sheet4 六类、拆分规则、品类映射 | 子项目草案 | 评香确认/改 | 不确定进“待拆分” |
| N05 品类映射 | 子项目有 L3 | L3→规范类/新类；缺 L3 提示 | 规则；`map_category.md` 兜底 | 品类映射 JSON、默认指标 | 规范类/新类/依据 | 评香确认 | 未知不允许推荐 |
| N06 任务类型/路由 | 子项目有品类/需求 | 判六类；精确产品/品牌/样品分流 | `route_task.md` | Sheet4 六类、拆分规则 | task_type + 路由 | 评香确认 | 不明确则“待定” |
| N07 目标 C 映射 | `recommend_brand` | 从产品/资料映射**所有符合**的 C（可多个） | `map_c.md` | C 本体、mapping_experience、品类默认 | 多个 C + 依据 | 必须确认 | 多候选让评香改，不自动唯一化 |
| 硬筛/召回 | 条件确认 | 新类、价格、A1（默认硬筛，可取消）/A23、品牌/产品（C 不硬筛） | 无（SQL） | 香精库、标签、市场标签 | 候选 | 可调条件/勾选 A1 硬筛 | 0 结果给原因 |
| C 计分 | 候选召回后 | 每个命中目标 C +3；无 C 则 0 分 | 无（确定性） | C 类型口径、候选 C 归属 | C 分 | 可调 C 集 | 无命中仍进候选 |
| AB 计分 | 候选召回后 | 所有目标 C 的固定 AB 并集与香精 A/B 交集，每个 +1 | 无（确定性） | C.ab_ids、香精 A/B | AB 分/总分 | 可调权重/短名单 | 无 AB 则 0 分 |
| N08 候选解释 | 结果生成后 | 说明命中/差价/风险 | `explain_candidate.md` | 候选、C/AB、价格 | 1–2 句解释 | 评香可改 | 模板降级 |
| N09 部门任务 | 子项目进入执行 | 六类→G 列任务 | `generate_department_tasks.md` | Sheet1/4、任务映射 | 任务清单 | 评香增删 | 规则模板保底 |
| N10 终点检查 | 选初样/终样/入库 | 检查三项默认要求 | 无（规则） | 规范类默认指标 | 通过/缺项 | 初样评香放行 | 缺项阻断终样/入库 |
| N11 问答 | 用户提问 | 检索故事/原文并带引用回答 | `qa.md` | 故事、简报、原文 | 回答 + 引用 | 无 | 资料不足直接说 |

## 2. 逐个节点

### 文件接收/解析

- **做什么**：PDF/Word/PPT/Excel/文本直接抽；图片走视觉；音频走 ASR；链接抓正文或保留链接+截图。
- **输出**：`artifact`（原件、文本、页/段/时间戳、解析状态）。
- **注意**：解析失败不丢原件；不把图片 OCR 文字当客户原话，除非确认是截图原文。

### N01 资料分类与标注

- **Prompt**：`prompts/classify_artifact.md`
- **参考**：`docs/输入端资料类型与读取方式.md`，`docs/重点关注信息经验.md`
- **输入**：文件名、文本、图片描述、用户备注。
- **输出**：
  ```json
  {"source_type":"客户brief|会议纪要|对标链接/图片|微信|销售输入|系统记录|寄样|报价|法规/检测|内部评香|邮件/附件|其他",
   "role":"需求|参考|反馈|法规|物流|外观|分析报告|其他",
   "free_tags":[],"note":"","confidence":0.0,"evidence":[]}
  ```
- **人工**：评香可改类型/角色/备注；低置信标“待确认”。
- **失败**：给“其他/待确认”，不阻断上传。

### N02 项目简报抽取

- **Prompt**：`prompts/extract_brief.md`
- **参考**：`docs/重点关注信息经验.md`、`docs/输入端资料类型与读取方式.md`、价格默认 `元/kg`
- **输入**：全部资料片段、附件清单、上一版简报、人工批注。
- **输出**：六组字段 + `evidence` + `confidence` + `open_questions`。
- **人工**：逐项改/确认；确认后写 `briefs.status=confirmed`。
- **失败**：字段留空；冲突写 `open_questions`；不编。

### N03 故事索引

- **做什么**：把项目资料按时间/来源/决策整理成可检索故事；保留原文引用。
- **Prompt**：可选 `prompts/story_summary.md`（只做摘要，不改事实）。
- **参考**：`docs/输入端资料类型与读取方式.md`
- **输出**：story sections（时间线、关键决定、未决、附件备注）+ FTS。
- **人工**：无需逐条确认；可加备注。

### N04 子项目拆分

- **Prompt**：`prompts/split_subprojects.md`
- **参考**：`docs/00_新版系统总览.md` 第4节、Sheet4 六类、`docs/06_推荐与打分.md`
- **输入**：项目简报、故事、资料原文。
- **输出**：
  ```json
  {"subprojects":[{"task_type":"find_product|match_sample|recommend_simple|recommend_brand|modify|create",
    "title":"","category_l3":"","target_products":[],"brand_filter":"",
    "a1":[],"a2":[],"a3":[],"price_target":null,"reason":"","source_refs":[]}]}
  ```
- **规则**：
  - 精确产品各自成 `find_product`；
  - 只到品牌/无精确产品成 `recommend_simple`；
  - 品牌 + 多个指定产品：每个产品一个 `find_product` + 剩余品牌一个 `recommend_simple`；
  - 客户寄样成 `match_sample`；
  - 改配方/创香分别成 `modify`/`create`；
  - 一个子项目只有一个主类型。
- **人工**：确认/合并/拆分/改类型。

### N05 品类映射

- **规则**：读 `data/品类映射.json`，L3 K 码 → 规范类/新类。
- **Prompt 兜底**：`prompts/map_category.md`（只在 L3 名称不标准时用）。
- **输出**：`category_l1/l2/l3`、`norm_class`、`new_class`、`mapping_basis`。
- **人工**：确认；未知时不得进入推荐。

### N06 任务类型/路由

- **Prompt**：`prompts/route_task.md`
- **参考**：Sheet4、`docs/00_新版系统总览.md`
- **输出**：`task_type` + `route`（find/match/recommend/modify/create）+ `reason`。
- **规则**：
  - 精确品牌+产品+版本 → `find_product`；
  - 客户寄样/竞品实物 → `match_sample`；
  - 只到品牌/香韵/价格 → `recommend_simple`；
  - 品牌客户/有定位/受众/包装/创意 → `recommend_brand`；
  - 锁定旧号+改动 → `modify`；
  - 从零创作 → `create`。
- **人工**：确认；`recommend_brand`/`create` 可由评香切换。

### N07 目标 C 映射

- **Prompt**：`prompts/map_c.md`
- **参考**：C 本体、`spec/mapping_experience.md`、品类默认、A1/A2/A3
- **输入**：子项目简报、资料原文、候选 C 字典（同新类）。
- **输出**：所有符合的 C：
  ```json
  {"c_ids":["C_xxx"],"primary_c":"C_xxx","items":[{"c_id":"","path":"","basis":"","confidence":0.0}],"unmapped":[]}
  ```
- **规则**：
  - 只能选同新类 C；
  - 可多选；多个 C 只是同义/父子时选最具体，不重复；
  - 无 C 则 `c_ids=[]`，不允许进入推荐。
- **人工**：必须确认；推荐前可增删。

### 硬筛/召回

- **输入**：新类、目标 C 集、价格、A1/A2/A3、品牌/产品、状态。
- **规则**：
  - 新类必须相同；
  - `recommend_brand` 必须命中目标 C 的**类型/口径**（选父类时子类同属；候选只需一条 C 命中）；
  - 价格 ≤ target × 1.2（无 target 不筛）；
  - A1 明确：命中任意 A1；
  - 无 A1 但 A2/A3 明确：命中任意 A2/A3；
  - 品牌过滤只用于 `recommend_simple`；
  - 精确产品只用于 `find_product`。
- **输出**：候选集 + 被排除原因统计。

### C 计分

- **输入**：目标 C 集、候选 C 归属。
- **规则**：每个命中的目标 C **+3**；多个目标 C 可累计；不封顶。
- **输出**：`c_hits`、`c_score`、候选自己的 C 列表。

### AB 计分

- **输入**：所有目标 C 的 `ab_ids` 并集、候选香精的 A/B 标签。
- **规则**：每个 distinct AB **+1**；`total = c_score + ab_score`。
- **排序**：total desc → c_score desc → ab_score desc → 价格差升序 → 爆品/中央库（展示用）→ code。
- **输出**：总分、C 分、AB 分、命中列表、价格差。

### N08 候选解释

- **Prompt**：`prompts/explain_candidate.md`
- **参考**：候选、C/AB、价格、市场标签
- **输出**：1–2 句“为什么推/风险/差价”；不得编造未命中的标签。
- **人工**：可改备注。

### N09 部门任务

- **Prompt**：`prompts/generate_department_tasks.md`
- **参考**：Sheet4 G 列、`docs/07_任务派发与完成终点.md`
- **映射**：
  - 找香：打样/寄样/调香/法规/质量
  - 对香：打样/寄样/分析/调香/法规/质量
  - 简单推荐：寄样/打样/法规/质量
  - 品牌推荐：寄样/打样/法规/质量
  - 改香：调香/入库/法规/质量
  - 创香：寄样/打样/法规/质量/调香/入库
- **人工**：增删/改负责人/截止。

### N10 终点检查

- **输入**：子项目、终点类型、默认指标、任务状态。
- **规则**：
  - 初样：只提示法规/稳定性/表现力风险，不阻断；评香放行留原因。
  - 终样：三项默认逐项核对；缺项不能完成。
  - 入库：同终样；生成配方登记信息。
- **输出**：`checks`、`blockers`、`override`。
- **人工**：初样放行；终样/入库确认。

### N11 问答

- **Prompt**：`prompts/qa.md`
- **参考**：项目故事、简报、原文、决策记录。
- **规则**：只答资料里有/能引用的；区分客户原话/销售转述/内部判断；不替客户承诺。
- **输出**：回答 + `artifact_id/locator/quote`。

## 3. 模型与配置

- **文本 LLM**：DeepSeek / Qwen（OpenAI 兼容），读 `data/config.json`。
- **视觉**：Qwen VL，用于截图、产品图、包装、表格截图。
- **语音**：Qwen ASR，用于会议音频；失败则要求纪要文字。
- **链接**：HTTP 抓取正文；失败保留链接+人工摘录。
- **禁止**：把 API key 写入 prompt、导出、日志。

## 4. 人工 gate 汇总

| Gate | 谁 | 不通过会怎样 |
|---|---|---|
| 附件类型/备注 | 评香 | 简报可能引错来源 |
| 项目简报 | 评香 | 不进入子项目拆分 |
| 子项目拆分 | 评香 | 不进入推荐 |
| 品类/新类 | 评香 | 不允许推荐 |
| 目标 C | 评香 | 不进入品牌推荐 |
| 候选短名单 | 评香 | 不派任务 |
| 终点/初样放行 | 评香 | 不完成 |
