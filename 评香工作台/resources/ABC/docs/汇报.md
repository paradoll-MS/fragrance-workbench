## 附录:执行层设计(本轮采用)

1. **三层拆分**:①确定性预处理(旧字段转换、无歧义别名命中、品类初筛、A3 规则映射、新品/爆品标识、产品候选底稿)——程序完成,不做 LLM 复核;②LLM 增量贴标(仅补 A2/B/C、校验品类与 A1/A3、产品歧义、未识别术语);③品牌产品身份核验——本轮沿用底稿候选,不联网阻塞清洗。
2. **上下文精简**:LLM 仅接收「精简 AB 字典(id+标签)+ 本批涉及品类的 C 完整判定树(闸门/叶子+左侧判定补充)」,完全移除 C→AB 关联映射、专家确认表、AB 别名全表等无关信息。
3. **输出最小化**:每行只输出增量与异常(`{"source_row": N}` 表示基线无异议);证据由程序按标签自动补证,LLM 不为每个标签撰写解释。
4. **直连 API 批量执行**:程序直接调用 DeepSeek chat API(`deepseek-chat`,temperature=0),并发 12,130 批 × 30 行全库耗时 **约 72 秒**,0 失败;每批成功立即落盘 `_work/batches/batch_NNN_result.jsonl`,程序校验行数/ID 并支持断点续跑(重跑自动跳过已有结果)。
5. **质量对照**:与人工试跑示范 33 行逐字段一致率见 `qa_vs_draft.json`;64 条校验错误(闸门误作 C 叶子、跨品类 C、伪 ID)均未写入输出,已入复核清单。
6. **C 判定语义**:仅按品类→闸门→叶子路径判断;允许合理弱推断;不通过 AB 反推商业定位 C;产品形态不明的洗护/织物行不强行贴 C。
