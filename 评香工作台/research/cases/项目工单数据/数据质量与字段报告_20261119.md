## 3. 三个新字段的落位

样品明细表新增三列，已并入 `sample_occurrences` 常用字段（原字段名与值同时留在 `source_records.raw_json`）：

| 原字段 | 含义 | 新列 | 有值行数 | 用法 |
| --- | --- | --- | ---: | --- |
| `F_SAMPLE_STORAGE_LOCATION` | 寄样库库位 | `storage_location` | 1,262 | 反查某库位有哪些香精、某个香精放哪 |
| `F_SAMPLE_QUANTITY` | 寄样库库存 | `stock_qty_text` / `stock_qty` | 1,198 | 判断还能不能补样，0 与空分开保留 |
| `F_SAMPLE_PERFUMER_QTY` | 调香师送样量 | `perfumer_qty_text` / `perfumer_qty` | 519 | 常见 10g（393 条），其次 5/30/20/50 |

说明：

- 库位统一为大写、去掉空格（源数据本身已是 `A8-2-3-16` 这种格式，2 条例外见第 6 节）。
- 与工作簿"新库位"页签相比，这批值**逐样品精确**，且有日期，所以按样品存放；原 `physical_samples`（库位快照 + 灌样记录 2,154 条）保留为历史快照，两者不互相覆盖。
- 覆盖率只有 12% / 11% / 5%，因为这三列只对近期寄样流程启用。空值代表"当时没填"，不能读成"没有库存"。

查询示例：

```sql
-- 某库位还放了什么
SELECT storage_location, internal_name, external_code, stock_qty, reported_ship_date
FROM sample_occurrences WHERE storage_location='A7-1-2-17';

-- 库存不足但最近还在寄的
SELECT internal_name, external_code, stock_qty_text, reported_ship_date
FROM sample_occurrences
WHERE data_state='current' AND stock_qty IS NOT NULL AND stock_qty < 30
ORDER BY reported_ship_date DESC LIMIT 20;
```

## 4. 品类归一：55 个"具体品类"→ 12 个应用品类

## 5. 保留策略：1 行"新快照已删除"的样品

对比两轮导出，有 1 条样品行在 11-18 快照里没有了：

- `LJB2620ALJ` 探雅精油皂 / 对客号 `DH-Y461912` / 寄样日 2026-08-17
- 原销售反馈："客户气味是认可的，打成精油皂颜色变化比较大，再不改变气味或者微变的情况下，减少变色因素"

它在源系统被删档，但这条技术反馈真实发生过、且后续确实改成"水质探雅精油皂"继续推进（2026-11-09 还在寄样）。所以本版**补录这一行**，用 `data_state='not_in_latest_export'` 标注，不混进当期数据：

```sql
SELECT count(*) FROM sample_occurrences WHERE data_state='current';              -- 10,818
SELECT count(*) FROM sample_occurrences WHERE data_state<>'current';            -- 1
```

规则写在 `数据源.json` 的 `carry_over_from`，下次换导出会自动重新比对，不会重复补。

## 6. 清洗做了什么 / 没做什么

**做了**

- 文本统一去首尾空白；空值归一（`无 / -- / 待定 / #N/A` 等视为空）。
- 内部香精号统一大写；`0`、`蓝色琥珀` 这类非编码值不进编号空间。
- 日期只存源表给的创建 / 最后保存 / 填报寄样，不推断"完成日"。
- 数值列双写（原文 + 解析值）：克重、加香量、香精单价、样品金额、库存、送样量。解析不出就留空，不猜。
- 同一段正文复制在多个样品行时，正文只存一份，每个原始出处都留链接。
- 新增 `category_group`（不动原 `category`）、新增 `data_state`（不动新快照）。
- 三套计数与源导出逐表对齐，57 项验收通过（`验收结果.json`）。

**没做（有意留给你定）**

- 20 个项目编号对应多个 ID（如 `XMBM202605130011`），像是复制或分期建项，**没有合并**，业务编号仍可能重复。
- 7 个客户 ID 对应多个客户名（改名或录入差异），`customers` 表保留源里的第一个名字，其余在 `raw_json`。
- 1 条寄样日期是 `2027-06-08`（沉香木（香水），创建于 2026-07-06），像年份手误，**没有改**。
- 2 条库位不是标准格式：`冰箱LC 242号`、`冰箱SY 451`（实际是冷藏柜位置），保持原样。
- 18 条样品没有内部号、177 条没有对客号、438 条没有克重：都是源系统漏填，未用别处信息反填。
- 12 个工单找不到所属项目（上一版 11 个），保留为"无项目工单"。
- 中央库仍是《【wip】中央闻香库20260623.xlsx》，本轮没有新工作簿，所以 3,862 条收录与标签未变。
