# 项目 / 子项目 / 任务 / 样品模型

更新：2026-10-28  
原则：一个项目多个子项目；一个子项目一个主类型；部门任务挂在子项目下；外部客户样品单独记录。

## 1. 项目 Project

| 字段 | 说明 |
|---|---|
| id / name / customer / brand | 定位 |
| sales / evaluator | 销售、评香 |
| grade | S/A/B/C/D，商业优先级 |
| status | draft / briefing / split / active / done |
| brief_id | 项目级简报 |
| story_id | 项目故事索引 |
| created_at / updated_at | 时间 |

项目级不放“新类/价格/目标 C”；这些属于子项目。

## 2. 子项目 Subproject

| 字段 | 说明 |
|---|---|
| id / project_id / title | 定位 |
| task_type | find_product / match_sample / recommend_simple / recommend_brand / modify / create |
| status | draft / briefed / mapped / recommended / tasks / sample_initial / sample_final / library_intake / done / cancelled |
| category_l1/l2/l3 | 客户三级品类；L3 必填（K001–K056 或标准名） |
| norm_class | 18 规范类之一 |
| new_class | 12 新类之一；推荐硬门槛 |
| target_c / target_cs | 品牌推荐目标 C；可多个，`target_c` 保存首个兼容旧逻辑，`target_cs_json` 保存全部 |
| a1 / a2 / a3 | 香型需求原词/本体 id；A1 明确则硬筛 |
| brand_filter | 简单推荐的品牌/大牌过滤；可空 |
| target_products | find_product 的精确品牌+产品+版本 |
| price_target | 元/kg；无单位按元/kg |
| price_elasticity | 默认 20（%） |
| endpoint | sample_initial / sample_final / library_intake；未定为空 |
| brief_id | 子项目级简报（覆盖项目信息+本子项目要求） |
| direction | 客户建议方向（如“花香-草本”）；每个方向一个子项目 |
| parent_subproject_id | 升级/拆分来源，可空 |
| base_formula_code | 改香的基准内部号；创香可放参考 |
| type_history | 类型变更记录 |
| created_at / updated_at | 时间 |

终点逐项核对另存 `endpoint_checks`：`subproject_id / section / code / label / status(pending/confirmed/na) / source(default/customer) / detail / note / updated_at`。客户资料里逐条写明的法规/禁用物/闪点等为 `source=customer`，前端红色高亮。

### 状态机

```text
draft → briefed → mapped → recommended → tasks
→ sample_initial → sample_final → library_intake → done
```

- `find_product`：`mapped` 后直接精确匹配；无结果 → 转 `create`（保留来源）。
- `match_sample`：需要 `external_sample` 收到后进入；评香对香后 → 推荐/转创香。
- `recommend_simple` / `recommend_brand`：`mapped`（品类/新类/C）→ `recommended` → `tasks`。
- `modify` / `create`：`briefed` → `tasks`。
- 任何类型可取消；类型升级保留历史。

## 3. 部门任务 DepartmentTask

| 字段 | 说明 |
|---|---|
| id / subproject_id | 归属 |
| type | 打样 / 寄样 / 分析 / 调香 / 法规 / 质量 / 入库 |
| title / detail | 任务说明 |
| owner / department | 负责人/部门 |
| due | 截止 |
| status | todo / doing / waiting / done / cancelled |
| depends_on | 前置任务 |
| payload | 香精号/数量/收件/法规市场等 |
| result | 结果/链接/备注 |

六类子项目默认任务：

| 子项目 | 默认部门任务 |
|---|---|
| find_product | 打样、寄样、调香、法规、质量 |
| match_sample | 打样、寄样、分析、调香、法规、质量 |
| recommend_simple | 寄样、打样、法规、质量 |
| recommend_brand | 寄样、打样、法规、质量 |
| modify | 调香、入库、法规、质量 |
| create | 寄样、打样、法规、质量、调香、入库 |

## 4. 外部样品 ExternalSample

| 字段 | 说明 |
|---|---|
| id / project_id / subproject_id | 归属 |
| received_at / received_by | 收样 |
| source | 客户/竞品/其它 |
| brand / product / version | 身份（可空） |
| description | 外观/气味/客户说明 |
| analysis_status | none / requested / done |
| analysis_result | GC/报告/评香结论 |
| matched_formula_ids | 评香对上的内部号 |
| result | 可推 / 需仿 / 待定 |
| notes | 备注 |

规则：没收到样品不能把 `match_sample` 标完成；“是否分析”由评香决定，分析作为部门任务。

## 5. 推荐 Recommendation

一次推荐保存：

- 子项目、task_type、new_class、target_c
- 硬筛条件：价格上限、A1/A2/A3、品牌、产品、状态
- 候选、AB 分、排序、算法版本
- 人工决定：短名单/淘汰/备注

## 6. 终点

| 终点 | 要求 |
|---|---|
| sample_initial | 只闻香；法规/稳定性/表现力只提示，评香放行 |
| sample_final | 三项默认逐项核对；缺项阻断 |
| library_intake | 同终样；生成配方登记（编号/版本/标签），不做库存 |

## 7. 审计

所有人工确认/修改写 `decision_log`：对象、字段、旧值、新值、人、时间、原因。LLM 输出只是建议，不直接改事实。
