# 数据归属与字段流转 v3

## 项目

`projects` 保存主身份字段、`customer_info_json`（客户/品牌/背景/对接人）和 `coordination_json`（总体交期、打样节点、收件、销售/评香、协调事项）。结构化完整简报在 `briefs` 中，`subproject_id` 为空。

`project.contacts` 每人可含姓名、职责、单位、电话、邮箱、渠道。`project.coordination_events` 逐条保存行动、负责人、原始及可解析交期、目的地、数量、用途、来源与 planned 状态。日期按资料发生时间解析，不以导入当天替代会议日期。

## 子项目

`subprojects` 保存品类映射、目标价与弹性、A1/A2/A3/B/C、硬筛配置、厂家要求、基准内部号、原样引用、参考/选定编号、`parent_subproject_id`、类型历史与执行状态。

`customer_requirements_json` 与子简报 `customer_requirements` 保持一致。上市资源分层在 `planning_json` 与子简报 `planning` 保存；客户 S/A/B/C 资源等级不等于本体 ABC 或项目商业等级。

项目共有事实可由理解输出 `shared_brief`，程序物化到适用子项目；专属要求只进对应子项目。不同子项目的价格、交期、基质、方向、禁用物互不覆盖。

## 流转与人工修改

子项目条件保存后同步子简报、当前筛选和未执行工单。换内部品类时清理旧 C 及旧品类范围。项目级共有事实改变，仅传播给仍等于原共有值的未完成子项目；局部覆盖值保留。人工改过的字段保存 manual_overrides，后续模型不能静默改回。

`brief_history` 保存每次简报版本；`decisions` 保存人工选择、字段修改、检查和模型应用记录。已执行工单保留派发时内容，待执行工单同步最新需求。

## 样品与附件

外部样品 `external_samples` 单独登记实际收样。客户说“已寄”只是资料信息。分析/调香附件存 `task_files`，后续调香工单可引用上游分析报告，不写入香精库。

改香的 `context_json.inherited_base` 保存父子关联、原样名称、实发工单、编号及来源状态。`base_formula_code` 仅保存可唯一确认的实际基准号。项目级客户与对接事项进入工单上下文，产品额外要求在子项目层按适用范围物化；空的子字段不会抹掉已知共有事实。

后续改香自动继承父项未撤销的产品、上市分层、价格与持续性合规/基质/性能要求，不机械继承旧配方或过期局部交期。比例修改必须同时更新气味结构及有效要求；冲突时做有界校验，旧配比保留在父项和修复审计。待执行、或等待编号同步的工单刷新需求，已执行快照保留。

项目客户/联系人/总体对接只在项目简报维护。子简报的项目组是继承快照，理解与新建时按项目权威信息物化，不能在子项目编辑器另立一份；API也拒绝子项改写项目字段。子项目页面和工单正文聚焦产品与本项要求。

## 2026-10-29 业务边界更正

客户三调/参考香材组合只辅助B/C，不直接映射A或主韵。A必须另有明确主体气味/主韵依据，推断记录evidence_role。customer_requirements仅限document/certificate/claim；普通气味、相容、性能、稳定性、数量、交期在普通简报中，历史原文保留于requirement_register，不作为额外证明清单。无真正额外诉求时为空。


## 应用层品牌 / 产品名称别名

`identity_aliases` 是跨项目复用的应用配置，保存kind（brand/product）、品牌、规范产品、别名、确认来源与创建时间。它不属于原始8张库表，也不是A/B/C术语或香精入库。新增和移除有decisions审计；删除某个项目不删除全局名称配置。目录主体及双语名关系由formula_product_labels的明确身份关系派生，近似/风格/母方参考不自动升级为同款。别名变更会刷新相关检索/推荐缓存签名，历史快照仍保留。
