# 香精项目 Copilot v3

v3 在独立目录、独立数据库和 8768 端口运行；沿用 v2 的原始资料、6 个历史项目与 6331 条香精记录。v2 的端口仍为 8767。

## 主流程

上传资料 → 解析与初步标注 → 点击开始自动生成 → 一次全景理解 → 故事、项目简报、子项目、ABC、确定性推荐与执行入口 → 人工选香或任务推进。

全景理解读取全部原文、页段定位、已有故事、各级简报、子项目与任务状态、样品和人工决定。不会在切换 tab 时分别调用简报、拆分和 C 映射模型。推荐与派发是确定性代码，不另问模型。

## 对象与归属

项目保存客户身份、背景、对接人、销售/评香、总体交期、对接事项和所有资料。每个独立产品、场景或实际任务目标形成子项目。子项目保存自身品类、价格、ABC、专属及继承要求、上市分层、局部交期、参考香和后续关联。

客户额外要求逐项保存 text/category/source_scope/source_refs/status。specific 是本子项目专属，inherited 是适用的共用要求。recorded 只表示已记录。后续工单携带这些要求、基质、添加量与来源。

## 六类子项目

- find_product：具体品牌、产品与版本身份检索；无命中可提交分析。
- match_sample：实际收样后评香对香；可用标签检索候选，结论由评香记录。
- recommend_simple：厂家目录式需求，额外提取大牌/品牌分支、爆品、新品。
- recommend_brand：结合定位、人群、风格、理念、场景来选香，包括创香前试香。
- modify：关联原香或原样，保留改动要求；基准内部号缺失时先确认。
- create：明确委托直接原创/仿香制作；需要来源原话。具体气味描述与要求先寄初样本身不足以判创香。

创香、改香也可提供库内参考候选；保存参考不会绕过调香直接派发打样。

## 两类推荐

默认内部品类、价格、A1（有则 OR）或 A2/A3 合并 OR 硬筛；B/C 不默认硬筛。厂家明确提出的大牌/品牌、爆品、新品要求默认硬筛。每项都能取消，内部品类可多选，也可手动锁任意 ABC 标签。

直接命中的 A/B/C 按 1/1/3 计分，硬筛标签本身不计直接分；再取需求 C 直接关联的 AB 并集，与候选自身 A/B 标签比较，每个 distinct AB 命中加 1。两个计分轮次独立，映射轮可再次命中直接硬筛的 AB。

## 增量和任务

已完成子项目保留；新一轮修改创建关联子项目。未执行且未选香的误路由可纠正，旧待执行工单归档并保存类型历史。执行中的任务不能直接换类型。

找香 → 精确检索 → 评香选择并打样，或分析 → GC 手动确认 → 调香 → 评香验收 → 打样 → 寄样 → 法规/质量。两类推荐选香后从打样开始。对香需要先登记实物收到。

## 2026-10-29 业务边界更正
