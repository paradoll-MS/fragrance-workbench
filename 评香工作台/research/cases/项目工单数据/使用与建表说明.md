`project` 返回所有匹配的源项目，展开全部工单、每次用样、需求、评香/调香备注、销售反馈、时间线、寄样记录和附件引用。加 `--details` 展开低频补充信息。加 `--json` 获取结构化结果。

**附件明确保留，不随字段精简删除。** 已保存1074条附件引用（需求附件440条、分析报告634条），包含文件名、文件ID、原元数据和关联项目/工单。当前为空的照片、稳定性、表现力、合规性、调香及评香报告字段，也保留附件导入映射，后续有内容时继续导入。终端项目档案和JSON均列出附件。原导出的引用未包含文件正文，目前不代表已经下载附件。

`sample` 同时支持内部号、对客号、名称及别名。结果区分中央库资料、实际用样和正文提及，能反查客户和项目。

明细原“样品报价”暂按样品金额保存，这是先前数值关系支持的解释，不表示开票金额；原“香精报价”独立保存为该次记录的公斤单价。两者的原字段和值都可追溯。

`search` 搜索项目、客户名称、人员、工单、香精名称和编号、所有业务备注及补充条件。短中文词使用子串查询，长词使用文本索引并补充子串匹配。默认最多30条，可用 `--limit` 调整。

`catalog` 只筛选【wip】收录的中央库。价格上限筛选采用工作簿里可解析、正数的单价；“100-200”等原文继续保留，不自动取中值。SQL系统价、项目目标价和每次寄样单价分别可查。

`customer` 按客户ID或名字列出已有项目；`raw 源记录ID --json` 展开任意来源记录。查询脚本始终以只读方式打开数据库。

如果让我继续使用这个库，可以直接说“查某项目的全部样品”“反查某香精的客户反馈”。工具可通过 `query.py` 的 `connect/project/sample/search/catalog/customer` 函数调用，无需启动服务。

## 建表方式与关系

完整DDL在 [schema.sql](C:/Users/26519/Desktop/本地香精库和项目工单/本地数据库/schema.sql)。源MySQL脚本作为文本解析，不执行其中的DROP、CREATE或INSERT。

| 表 | 一行代表什么 | 设计理由 |
| --- | --- | --- |
| `customers` | 一个源客户ID | 客户名称与多个项目关联 |
| `projects` | 一条源项目ID记录 | 业务编号可能重复，关联使用源ID |
| `work_orders` | 一条源工单ID记录 | 项目到执行任务的一对多关系；无项目的工单也保留 |
| `formula_refs` | 一个内部香精编码；另有未编号占位记录 | 串起中央库、库外项目用样、SQL资料及实物记录 |
| `catalog_entries` | 一条不同的【wip】收录资料 | 中央库范围按【wip】，同号多名、多应用、多价格可并存 |
| `sample_occurrences` | 一次工单中的用样记录 | 同一内部号多次寄送或不同对客编号分别保存 |
| `notes` / `note_links` | 一段项目内相同角色的文字及所有出现位置 | 反馈复制到多样品时聚合阅读，保存每条原始关系 |
| `shipment_mentions` | 一个记录里的一条运单/交接引用 | 一工单可多次寄送，一运单可跨工单；填报日期分别保留 |
| `physical_samples` | 一条库位或灌样记录 | 库位快照与灌样日期不是同一种库存事件 |
| `events` | 可从记录直接取得的创建、最后保存或填报寄样事件 | 操作时间、填报日期和业务发生时间分开 |
| `attributes` | 一项补充条件或资料 | 不给低频、稀疏字段增加大量固定列 |
| `aliases` | 一个名称与内部号的关系 | 对客名附带项目/用样上下文，不全局覆盖内部名 |
| `attachments` | 一个附件引用 | 保存文件名、远端ID和原元数据；引用不代表本地已有正文 |
| `directions` / `direction_links` | 一个明确命名的项目方向及其原文关联 | 已将两复盘项目的9个方向标注；其他项目的方向仍可从全文查询 |
| `formula_mentions` | 正文明确提及一个已知内部号 | 这是提及关系，与实际用样区分 |
| `source_files` / `source_records` / `imports` | 来源文件、原始行及本次导入 | 保存原文JSON、源位置、文件哈希、操作人和时间 |
| `record_links` | 合并或补充记录的来源连接 | 纯重复中央库行折叠后，仍能追到每个原始行 |
| `search_documents` / `search_fts` | 一个可搜索对象及文本索引 | 支持中文、短词、编号与全文检索 |
| `field_decisions` | 一个源字段的取舍决定 | 记录常用、正文合并、补充、元数据或仅原始资料的去向 |

关键关联：

```text
客户ID → 项目ID → 工单 F_WO_PROJNAME → 工单ID → 明细 REF_ID_
                                      ↓
                           每次用样的内部号 → 香精编号引用
                                               ├─ 【wip】中央库资料
                                               ├─ SQL补充资料
                                               ├─ 库位/灌样记录
                                               └─ 其他项目的实际用样
```

项目无工单、工单无样品、库外样品都保留。中央库同号的完全相同行折叠，不同名称、应用或报价继续保留。编号只做首尾空白和大小写整理，保留版本字母、后缀和原有标点；“0/蓝色琥珀”使用未编号记录，不当成可靠配方编码。

常用视图：

- `v_project_overview`：项目、客户、负责人员、操作时间、工单与样品数量。
- `v_sample_trace`：一次用样与项目、客户、内部号、中央库收录状态。
- `v_catalog`：按香精编号汇总中央库的名称、分类和来源记录数。
- `v_note_context`：聚合笔记、全部源位置、来源记录最后保存时间。
- `v_shipment_groups`：按项目和运单归组，保留不同填报日期。

## 少量业务 hint

以下是本批记录支持的阅读线索，作为可能性提示，不自动改写成事实：

1. **评香备注可能承担技术任务书和协调日志。** “改某配方”“先测后寄”属于安排，“已确认/已测试”才可能是结果；具体作者与执行人按记录另看。
2. **销售反馈可能是一轮新brief，也可能是内部物流说明。** 一段话挂在旧样品行上，不代表它发生于原寄样日；复制到多行也不代表每个样品都被客户选中。
3. **同张工单可能反复追加并改变服务方向。** 用工单创建日或最初标题理解全部后续内容，可能遗漏真实进展。
4. **字段名可能与实际用法偏离。** 原“指定评香师”的一组值实际重复业务员，“补样优先级”常填克重。新库将前者移出评香字段，后者记为补样参考量；原值仍可查。
5. **项目流程结束、样品评价达标和客户最终确样可能是不同状态。** 本库并列保留来源，不据一个状态自动推断其他环节完成。

## 时间和结果怎样阅读

`events` 只存源记录可直接支持的时间：创建、最后保存、填报寄样日期。不会据“需要8/28”造出一次8月28日完成事件，也不会据最后更新人推断某段备注作者或快递交寄人。

同一份反馈可能留在7月用样行、8月最后保存，界面显示“来源记录最后保存时间”，不称为客户实际反馈日。正文中的明确日期、计划、版本和浓度继续在原文中保留。

文本标签由规则生成，只辅助查找；方向标注目前覆盖已人工复盘的两个项目。其余项目的全部原文、工单、样品和时间都已导入，未标注方向不表示没有方向。

## 香精库新类与四维标签

中央库新增一个“新类”和四个独立维度：核心定位、香气感知与情绪、场景风格适配、常见香型香调。分类标准取自《各品类选香维度标签_改进.emmx》。一支内部号只保留一个新类，同号多条库内资料共同提供线索；客户项目仍使用原三级品类。

这五项是香精库的查询标签，另建扩展表保存，不扩展每个项目的常用字段。初始标注综合名称、香气资料与对应项目需求，保存依据；人工确认后优先保留。未能判断的格子允许空白。

| 扩展表或视图 | 用途 |
| --- | --- |
| `library_taxonomy` | emmx节点、层级、新类、维度及完整路径 |
| `library_labels` | 每支香精唯一的新类、依据、试标批次及复核状态 |
| `library_dimension_tags` | 四个维度各自的标签路径与依据，可多选 |
| `library_label_runs` | 规则版本、分类标准文件与哈希 |
| `library_review_history` | 人工回写前后的结果及来源 |
| `library_history_reviews` | 每支香精每个项目的历史语境判断，区分实际用样和正文提及 |
| `v_library_labels` | 将新类与四维合并为一行，方便查询和对接 |

例如在本目录运行 `查询.cmd catalog --new-class 空间香氛 --core 酒店大堂`。`sample` 与项目档案中的中央库用样也带上库内标签。源数据重建时保留仍在中央库中的标签和人工复核记录。
