# 简报与项目故事

更新：2026-10-28

## 1. 项目简报

六组字段：

1. `project`：项目名/客户/品牌/销售/评香/日期/摘要。
2. `product`：产品名、L1/L2/L3、内部应用、新类、形态、用法、基料、加香量、**目标人群**。
3. `scent`：主题、核心定位、**建议方向 directions**、**各方向描述 direction_notes**、参考产品、家族、三调、感受、场景、排除项、强度/留香/扩散。
4. `commercial`：目标价、价格段、终端价、年量、MOQ、上市、打样、市场、渠道。
5. `compliance`：市场、法规、过敏原、清真、闪点、稳定性、颜色、基料测试。
6. `deliverables`：类型、数量、收件、截止、备注。

每个字段可以带 `evidence`（artifact_id / locator / quote）和 `confidence`；缺的留空，不编。

## 2. 重点关注

见 [重点关注信息经验](重点关注信息经验.md)。尤其：

- 价格无单位直接按元/kg，不再生成“价格口径待确认”，只有税/币种/成品价才另问；
- 法规必须带市场/品类/版本；
- 对标要带目的；
- 寄样状态分阶段；
- 需求目标不等于已实现结果。

## 3. 项目故事

故事不是一篇总结作文，而是可检索的存档：

- 资料时间线：谁在什么时候给了什么；
- 关键决定：评香/客户确认了什么；
- 未决问题；
- 原文引用；
- 附件备注。

问答只基于故事/原文回答，必须带引用；区分客户原话、销售转述、内部判断。

## 4. LLM 节点

- `prompts/extract_brief.md`：项目简报抽取。
- `prompts/qa.md`：项目问答（检索 + 引用）。
- 故事索引目前由规则生成；可选 `story_summary.md` 只做摘要，不改事实。

## 5. 当前限制

- 故事页目前是资料/简报时间线；语义检索/全文索引后续补。
- 问答是关键词检索 + LLM；没有命中时明确说资料不足。
