# UI ／ 三个页面与交互约定

前端是原生 JS，没有构建步骤。`frontend/common.js` 提供 `h()`、`api()`、`dialog()`、`run()` 等最小工具，页面文件只写自己的渲染。

## 1. 页面

- `project.html?id=` 项目详情。从上往下：项目标题与进度、待处理（有才显示）、交付方向、开发子项。
- `index.html` 项目列表。每行：名称、类型、客户、目标位进度、待处理数、更新时间。
- `select.html` 选香。查询框 + 模式，结果分「推荐 / 线索 / 同类候选」，带分页。
- `mock.html` 模拟中台。页面在 `mock_platform/`，与业务前端分开；部门默认回执、待处理任务、最近回执。

页面之间只靠 URL 参数与项目 id 连接，没有前端路由。

## 2. 项目详情页的结构

一个方向一张卡：标题、入口、终点、状态、轮次摘要。一个目标一张卡：名称、入口、终点、需求简报、方案区、目标位。

需求简报按客户原话排：香气要求占一整行，左侧用暖色竖线压住；下面是人群、市场、添加量、价格。
「合规与客户要求」折叠，只露前 12 条，其余指向检查清单。标签一行显示 C 名称，悬停看依据；
模型没映射的词单独一行，不混进标签。没有打标时提示会在首次检索时生成，而不是显示空白。

颜色只用三处：暖赭（方向与香气）、松绿（标签与通过）、砖红（失败与阻断），其余是黑白与纸色。
分隔靠 1px 细线和粗细差异，不用阴影、圆角卡片堆叠和渐变。

一个目标位一行头：策略、阶段、香精编号与版本、是否暂存。下面依次是：

- 开发任务块（有 job 才有）：dev_type、第几次、GC 报告、试作、是否已验收。
- 动作区：当前阶段可点的按钮，置灰的显示原因。
- 检查清单块：版本、范围、条数、各状态计数、放行记录、可展开的按部门清单。
- 部门任务：部门、任务类型、外部编号、回执状态。
- 寄样记录：kind、香精、版本、形态与数量、时间。
- 该目标位的问题：原因与下一步。

没有方案的目标只显示策略按钮；点开后是内联表单，选香跳选香页，仿香/创香/改香填参照与补充要求。

## 3. 动作命名

按钮文字就是业务动作，不加「确定」「提交」这类空词：

- 生成检查清单、派发检查、初寄样放行、正式寄样放行、入库放行
- 准备样品、派发寄样
- 确认 GC、验收试作、退回调香
- 派发入库、确认入库
- 暂存

对话框标题用同一套词，例如「生成检查清单」「正式寄样放行」。

## 4. 错误与阻断

- 业务阻断：命令返回 `blocked` 与 `issues`，页面把第一条的「缺什么 + 下一步」用 toast 显示；按钮本身在动作区已标灰并写明原因。
- 参数错误：HTTP 400，页面 toast 显示后端那句中文说明，例如「项目名称不能为空」「该回执已处理」「目标位已更新，请刷新」。
- 网络或服务异常：toast 显示「请求失败（状态码）」。

错误只说对象与下一步，不写「操作失败，请重试」这类没有信息量的话。

## 5. 视觉

- 一列 1040px，白底，分割线浅灰。卡片圆角 10px，阴影只用于对话框。
- 颜色只有五种语义：正文、次要、线、底色、强调（蓝）；通过绿、待办黄、不符红只用在状态 chip。
- 字号三档：标题、正文、次要。表格化信息用 `row` 与 `grid2/grid3` 排，不用真表格。
- 留白靠间距，不靠边框；一段信息一个 `stack`。

## 6. 交互约定

- 每个写操作都过 `run(button, task)`：按钮禁用、toast 结果、失败恢复。
- 对话框关闭即销毁，不保留状态；需要重开的从当前数据重建。
- 列表为空时给一句「下一步做什么」，不留空白页。
- 页面只显示当前能做的事，不显示「将来可能」的功能。
