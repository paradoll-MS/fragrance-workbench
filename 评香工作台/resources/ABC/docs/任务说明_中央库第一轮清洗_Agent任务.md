# 中央闻香库第一轮冷启动 · 重复任务 Agent 指令

## 0. 目标与边界

你负责将中央闻香库的每款香精转为可供 wanted 的品类筛选、ABC 匹配与产品身份检索使用的结构化资产。本轮是冷启动：有意义的候选覆盖优先于精确率，允许弱证据贴标；不强制填满 ABC，不制造无证据标签。原始数据不可覆盖。

本轮只用《【wip】中央闻香库20260623.xlsx》中的 Sheet1、品类字典、字典香族、评香词典等旧库字段，以及香精名称。不得读取历史工单、历史需求、历史工单推断标签；第二轮另行补充。公开网页仅用于核验名称提示的品牌及商业产品身份，不得将外部原香的香调、广告定位、成分表直接当作库存香精实际属性。若后续允许外部原香辅助贴标，另建证据层，不混入本轮。

输入：
- 原始中央库 Excel（以 Sheet1 原始行号、原存货编码作为输入标识）；
- 《品类与ABC标签体系_V2.xlsx》：应用品类、A标签、B标签、AB别名、C标签树、C左侧判定补充及 LLM判断规则；C到AB关联映射仅供理解与日后评分，不能直接回写 AB 或反推出 C；
- 《中央库冷启动_试跑与品牌产品候选.xlsx》：品类旧值转换、旧香族转换、试跑示范、品牌字典、产品身份字典、香精产品候选关系、全库第一轮预处理、重复编码待处理和输出模板字段。预处理、示范和品牌候选均为待核对底稿，不是已确认答案。

## 1. 工作分工：程序先做确定性处理，LLM 做语义判断

1. 程序读取全部源行，完整保留原编码字符串、原名称、原品类、价格、入库逻辑、旧标注。先输出行数、唯一编码数、重复编码及缺失／0 编码清单。不要用名称合并香精；不要删除编码版本后缀。0、空码的记录用 source_row 暂存，待确认真实编号，不写入正式身份表。重复编码在属性一致时合并证据，冲突时保留不同源行并进入核对；不能凭相似名称合并配方版本。
2. 程序加载字典，建立 tag_id→名称/层级、别名→候选 ID、category_id→品类、C id→完整路径/节点类型、旧香族及品类转换表、品牌产品别名字典。所有词义不唯一的别名返回候选，交 LLM 在上下文判断。
3. 按记录调用 LLM 进行标签判定、品牌／产品线索识别。LLM 输出受字典约束的结构化 JSON；每条标签有简短依据和证据等级。不得让 LLM 创建正式 tag_id、category_id、brand_id、product_id；新品牌／产品先输出候选名称，经程序去重后分配 ID。
4. 程序校验、归并、生成输出；失败记录明确原因，修复后重试。每批可独立复现，不反复运行成功记录。

## 2. 品类

优先读二级、三级品类，再结合品类备注和名称中的明确应用信息。三级为具体用途，不一定要做成标准品类。织物洗护传统、新型及混合一律归织物护理；口腔护理归口腔护理（含唇部），再依据用途选择口腔或唇部 C 路径。其他家庭护理等宽泛字段需要三级/备注支撑；明确硬表面清洁可归硬面清洁。ALL 保留为旧应用范围，不自动写入全部12个品类；清真、食品、其他等非标准或歧义值不要硬塞入标准品类。二级和备注冲突保留主品类与备选证据，不直接认定两个品类均适用。多品类必须有各自证据；分类仅用于检索，不代表法规、稳定性及表现力检查已通过。

## 3. 原生 ABC 判定

证据优先级：明确的主韵关键词、三调、已填旧香族/子香族/风格/人格及联觉信息 > 名称中的明确气味词 > 合理的名称联想。注意旧字段可能相互冲突，不能盲目照抄，也不能因名称更有趣而覆盖旧评香信息。优先保留有明确依据的值，冲突记录进入待确认；普通名称弱证据可直接贴入 trial 标签。名称里的营销词、降价、性价、原版、编号、清真、爆香等并非气味描述。

- A1：可辨认的气味对象，允许名称中真实气味词提供弱候选。长词优先，例如佛手柑不是佛手；紫罗兰叶与紫罗兰区分；桉叶/尤加利根据别名映射。不要从专有香水名（如尼罗河花园、COCO小姐）凭空解析实际香料。A1 表示闻感，不表示真实配方成分。
- A2：实际可理解的香韵、气味特征。可从直接描述或有把握的 A1 语义得到弱候选，例如鲜茉莉→花香；不把 C 关联输出直接写入。三调/主韵中的“木香”“白麝香”“奶香”“青绿”等映射至实际字典。不要把香族中的“琥珀”一律当作琥珀香韵（旧香族主要表示东方母型）。
- A3：整体香调。优先用旧子香族→A3 的固定转换，如青滋木质→青绿木质调、琥珀香族→东方调（仅当子香族无值）。旧子香族不是 A1/A2；不把母型与子型重复贴作多个命中。没有旧香调时，如果名称或主韵明确是结构/母型，可给弱候选；不能从单个原料或多种原料随意构造复杂香调。主韵与子香族冲突时记录复核，不随意覆盖。
- B：旧风格、人格、情绪及联觉具有较高价值；例：香水香氛→香水感，天然/洁净→天然感、洁净感，中性独立→中性印象、独立自信，女香→女性印象，舒缓→放松舒缓；不是配方或安全结论。描述不足可以留空。蓝色琥珀可给冷色调弱候选，但不能只因产品名“蓝”“黑”“白”就普遍贴联觉标签。
- C：先确定标准品类；使用该品类内 C 完整路径，从闸门下钻至合法叶子。只有明确或合理弱语义支持该定位时贴标：例如身体洗护的旧“香水香氛”可以支持香水转化；空间香氛的明确茶香调可以支持茶香调叶子。不得把 C→AB 当成 AB→C 的推导规则：木质+麝香不自动等于通勤商务、北欧风；同一 A3 与 C 香调叶同义的情况可根据原始香型证据分别贴标。具体旧香调在该品类无对应 C 叶时允许退回有充分语义支持的母型（若存在），否则 C 留空，不发明标签。不凭应用品类本身就推定经典香型或人群/场景。

未识别术语收集到 unresolved_terms，重复术语汇总；不要临时扩大字典。

## 4. 新品、爆品、品牌与产品身份（与 ABC 并行）

- is_new = 入库逻辑明确为“新品”；is_hot = 入库逻辑明确为“爆品”。0表示原库未标记，不是对市场现状的断言；不通过数字、原版、新配方、性价等名称猜新品/爆品。保留 entry_logic_raw；同编码有多个来源时保存所有原始值，任一来源明确标识则保留该标识，冲突可复核。
- is_big_brand_dupe: true/false/null（null=未知；只有可靠内部依据或人工确认才能写 true/false）。另输出 dupe_status：confirmed / strong_candidate / ambiguous / brand_only / unidentified / rejected。对未确认的强候选不要丢失，可以提供给评香选香和确认；不得仅凭原香网页存在就把仿香关系标为 confirmed。"大牌"业务范围尚未定义，品牌目录可先广纳经典商业香、独立沙龙、区域品牌、日化、酒店香氛等候选，不等于大牌属性已获确认。
- 名称先去除仅用于内部报价、改版、应用形式的附加词，保留 original_name 与 normalized_search_name；数字、EDP/EDT、浓香、版本、年份、颜色、男女版、系列信息可能决定具体商业产品，不得粗暴清除。多个库存版本可以指向同一商业产品，但库存编码仍分别保存。
- 按已有品牌、产品别名字典检索。显式品牌+完整产品名、独特产品别名、英文名、双语名称为强线索；普通香韵名称、短词、单个品牌名、仅相似译名为歧义候选。对重复的标准化公开产品名去重查询并复用核验缓存，不对每个库存行重复联网。
- 有产品线索时检索公开产品名称与可能品牌，优先品牌官网/官方产品页，次选可信香水目录或零售资料。只发送公开商品名/通用别名，不把内部编码、配方、全库记录发给搜索服务。登记标准品牌名（中外文）、品牌别名、产品原名、中文名称/别名、版本信息、公开核验 URL、identity_status。多个候选保留多个，不强行挑选。网页核验不到的标待核验，不杜撰 URL。产品存在核验和内部香精仿香关系确认是两个独立状态。
- 产品身份层允许 product_family_id（系列）、product_id（具体产品）、edition（浓度/版本/年份等）；版本不明的关系只作为系列级候选，不进入 wanted 的 find_product 精确命中。某品牌只有名称不能给其随机分配热门产品；例如单独“香奈儿”=brand_only。名称“绿茶”不等于雅顿绿茶；“蓝风铃”可能是花香也可能是 Jo Malone 产品；“黑鸦片洗衣液”可以有明确产品候选，但仍须核实仿香关系和原香版本。

## 6. 分批执行、汇总和质量检查

- 先做确定性的全库预处理，依据已提供示范选取30–50行跨品类样本（含名称、旧标注、重复编号、缺失品类、歧义品牌、明确仿香线索），校验规则。然后按原编码/源行排序分批执行，建议每批25–50行或按实际上下文大小缩减；每批使用该品类 C 子树及完整路径、AB 字典、相关别名和待识别产品字典。不可截断字典造成合法标签遗漏；若分阶段召回标签，保留未匹配词供二次检查。
- 输出中间 JSONL，每行一个原记录结果；记录 batch_id、source_row、input_hash、taxonomy_version、状态、错误原因，支持断点续跑。仅重跑失败记录与版本变化影响的记录；不要覆盖已确认的人工作业。
- 程序校验：每行输入有对应结果（成功/待处理/失败）；所有 ABC ID 存在且层级相符，C 必须叶子、品类相符；同一香精同一标签去重，A/B 不需绑定品类、C 绑定品类；未确认产品不进入精确匹配；名称、原标识与源表一致；重复编码冲突不得静默合并；品牌产品别名歧义不得静默选定；空标签保持空，不填其他标签代替。
- 抽查：至少覆盖每个实际出现的标准品类、旧标注和仅名称记录、所有新品/爆品标识冲突、重复编号、强线索产品、歧义和未识别产品的样本。抽查是找系统性错误，不要求评香逐款批准才能发布 trial 数据。
- 生成结果：fragrance.jsonl（唯一有效编号主视图）；fragrance_tags.jsonl（每条标签一行，证据及状态）；brand.jsonl、product.jsonl（品牌及产品目录、别名、版本与核验 URL）；fragrance_product.jsonl（每个候选关系一行）；review_queue.xlsx（重复、缺码、品类冲突、未匹配词、产品歧义及未完成核验）；batch_manifest.json（覆盖率、失败与复核统计）。另导出人可读的 Excel，ID 与中文名分别列出，保留原字段及 source_row，供评香查看。对历史工单留出未来 evidence_source=history，禁止本轮提前使用。
- 汇报至少包含：原始行数、唯一有效编码、缺码与重复数、有效标准品类覆盖率、A1/A2/A3/B/C 非空比例和分布、已核验商业产品数、产品候选关联数、未确认/已确认仿香数、新品爆品原始标记及去重计数、错误与复核清单。不要把产品候选数写成仿香确认数。

## 7. 对 wanted 的接口约束

在线 query 模式与离线 fragrance 模式共用冻结的 ABC 字典与 C 语义知识，但不共用证据规则。query 处理目标需求；fragrance 只标库存已有或合理推断的属性。filter_fragrances 使用标准应用品类、新/爆及经确认的目录属性；不确定产品可在候选入口展示，不能伪装成精确命中。F00 的 C→AB 映射只参与评分，不写回香精原生 AB。日后映射更新无需重标全库。工单阶段追加独立 evidence，不覆盖本轮或人工确认结果。
