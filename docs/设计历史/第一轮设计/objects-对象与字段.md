# Objects ／ 对象与字段

## 1. 结构和共同约定

- 业务层级为 Project → Subproject → Round → Goal / PlanSlot → DeliveryAction 或 DevelopmentJob → DepartmentTask。Goal 挂子项，PlanSlot 挂轮次并指向 Goal；同一目标可跨轮换方案。每条寄样及入库回流均指向目标位。
- 资料层为 Source → SourceSegment → SourceRef，挂项目，可被多项引用。理解层为 IntentDraft → BriefRevision → 调用时冻结的任务简报。
- 独立资产层有 CatalogFragrance、ProductIdentity、ProductRelation、FormulaVersionRef、ExternalSample、MaterialSample、Evidence。工作流只存引用和必要快照。
- 所有 ID 和源编号都是字符串。自建 ID 不直接复用源编号；中台 ID 存在 ExternalRef 中。未查到为 null，已知为空为 []，显式禁用用枚举或布尔。数字以明确单位的十进制定点值保存。金额必须带币种和计价单位，数量带单位，原文同时留存。
- 可提取的值沿用 `FieldValue{value, raw_text, source_refs[], origin, verification}`。origin 取 source、derived、default、manual、adapter；verification 取 proposed、confirmed、conflicting。manual 记录操作者、时间和原值。应用自己的字段更新用 expected_revision，初建和命令重试用 command_id。
- 所有时间保留事件发生时间和系统接收时间。有时区的时间转 UTC 存储。只有月份和日期时保留部分日期及原文，补年需要可追溯的资料日期或人工确认。

## 2. 项目、资料与简报

1. **Project**。字段为 project_id、external_refs[]、kind（customer、internal_upgrade、invent）、name、customer_id?、customer_name?、contacts[]、owners[]、shared_brief_revision_id?、status、revision。全项目交期、供样约定、背景归共享简报。收件信息作为 ContactRef 保存，生成寄样任务时冻结。
2. **Source / SourceSegment / SourceRef**。Source 有 source_id、project_id、format、filename_or_url、blob_ref?、sha256、received_at、occurred_at?、note?、parse_status；段有 segment_id、source_id、locator（页／幻灯片／工作表单元格／时间码／段与字符范围）、content、extraction_kind（verbatim、ocr、transcript、visual_description、manual_excerpt）。引用含 segment_id、start/end 或整段、quote?。视觉描述、未核实 OCR 与转写需显示其形态。Source 可附原件、解析版本和未读定位。
3. **ParseRun / ModelRun**。run_id、source_ids 或 scope_id、input_fingerprint、status、pipeline_version、model_id?、model_params?、effective_versions、result_ref?、issues[]、started_at、finished_at?。保存阶段与原始模型提案，失败保留部分成功片段和上一版确认结果。
4. **IntentDraft**。draft_id、project_id、input_fingerprint、intents[]、unassigned_refs[]、issues[]、parse_run_ids[]。每个意图片段有 key、source_refs[]、action_proposal（new、supplement、inherit_modify、continue、resend、unknown）、linked_subproject_candidates[]、intent_signals、proposed_brief。模型输出候选引用，ID 分配由业务层执行。
5. **BriefRevision**。brief_revision_id、project_id、subproject_id?、round_id?、supersedes_id?、facts[]、fields、origin、actor_id、created_at。fact 保存 key、value、source_scope（project、subproject、round）、source_refs、applicable_to[]、value_origin、state（active、superseded、conflict）。字段包括 brief_original_refs、end_product?、application_category_ids[]、review_category_id?、market_countries[]、use_scope?、base?、dosage?、process_packaging?、special_use_or_claims[]、price_target?、required_count?、deadline?、sample_form?、quantity_per_item?、delivery_group?、customer_requirements[]、intent_detail。price_target 含 floor?、ceiling?、target?、currency?、per_unit?、is_explicit_limit、raw_text。客户要求含文本、来源、must_or_preference、proposed_metric_id?、conditions、criteria?、due_stage? 和 document/claim/test 等类型。普通感官、操作和价格事实保留在对应表单，只有可验证交付要求转检查，未识别但明确提出的检查进入人工分类。
6. **分型详情**。CatalogBrief 保存目录树选择及新/爆/大牌标志。BrandBrief 保存 positioning、audience、style、olfactory、context、concept、scenario、negative_attributes。ProductTarget 保存 brand_text、product_text、edition_text?、要求本体的依据、selected_product_id? 和身份状态。SampleBrief 保存 external_sample_id?、similarity_text?、similarity_grade?、changes[]、retained[]。ModifyBrief 保存 base_fragrance_ref?、base_formula_version_id?、source_shipment_line_id?、changes[]、retained[]。这些是 BriefRevision.intent_detail 的有类型内容，可留未知。

## 3. 需求、轮次与执行

1. **Subproject**。subproject_id、project_id、requirement_type（find_product、with_sample、recommend_simple、recommend_brand、modify、undecided；开发子项另有 development_type）、final_endpoint（shipment、warehouse、warehouse_return）、parent_id?、parent_round_id?、parent_slot_id?、inherit_id?、source_round_id?、source_shipment_line_id?、current_round_id、current_brief_revision_id、revision、status。parent* 是成果回流地址，inherit* 是历史出处。子项可各自推进。
2. **Round / Goal / PlanSlot**。Round 有 round_id、subproject_id、no、kind（initial、continue、resend）、previous_round_id?、current_brief_revision_id、search_query_id?、rejected_fragrance_ids[]、status。Goal 有 goal_id、subproject_id、min_count_group_id?、label、is_required、endpoint、delivery_quantity?、requested_sample_form?、status。一个 Goal 对应一种实际交付的香精或明确的复寄行。PlanSlot 有 slot_id、round_id、goal_id、strategy（select、duplicate、create、modify、resend、adopt_existing）、state（planned、active、superseded、complete、cancelled）、fragrance_ref?、development_job_id?、action_snapshot_id。绑定正式回执前可以换 slot，旧实发和在途任务保留。每个 Goal 至多一个当前 slot，重复款默认只计一个推荐款数，同款复寄单立 Goal。
3. **组合与数量**。DeliveryGroup 记录 group_id、goal_ids[]、requested_range?、confirmed_count? 和 mandatory_goal_ids[]。多款先冻结明确必选款，再由评香确认总数并以当前目标位核算。确认的总数含必选款；目标缩减需理由。未给款数时允许先选、开发、备样；在放行正式寄样的清单确认时由评香确定目标范围。数量用于实际寄样满足度，与款数独立。
4. **DevelopmentJob / Trial / Evaluation**。job_id、subproject_id、slot_id（执行所属目标位）、development_type、confirmed_brief_revision_id、reference_type/id?、analysis_sample_id?、gc_report_id?、base_formula_version_id?、current_iteration、approved_trial_id?。GCReport 有 gc_report_id、analysis_sample_id、task_id、attachment_ref、structured_data?、anomaly?、confirmed_by?。Trial 有 trial_id、job_id、iteration、trial_fragrance_id、formula_version_id、trial_sample_id?、perfumer_notes?。Evaluation 有 evaluation_id、trial_id、verdict、comments、actor_id、evaluated_at。新版本重新做受影响的检查。
5. **DepartmentTask / Result / WorkflowIssue**。Task 有 task_id、project_id、subproject_id、round_id、slot_id?、department、task_type、spec、spec_hash、dependencies[]、deadline?、assignee?、attempt、status、external_task_id?、created_at。状态为 queued、sent、in_progress、partial、done、failed、cancelled。Result 有 event_id、task_id、external_task_id、task_attempt、env、payload、occurred_at、received_at、validation_status。Issue 有 issue_id、scope_type/id、node、reason_code、missing_fields[]、waiting_for[]、next_action、resume_events[]、owner?、due_at?、state。发送失败可用同尝试重投；重做业务任务生成新尝试。
6. **WarehouseRecord / DevelopmentReturn**。入库凭证含 warehouse_record_id、task_id、fragrance_id、formula_version_id、trial_id?、check_set_id、approved_by、effective_at、status、external_refs[]。已有香的内部替代另存 adoption_id、source_warehouse_record_id、approved_by、reason、check_set_id。DevelopmentReturn 保存 job_id、warehouse_record_id、parent_slot_id、target_round_id、status。子项已成功回写原目标位后完成，已撤销目标回执进入异常待认领。
7. **ShipmentPlan / Shipment / ShipmentLine**。计划含 shipment_plan_id、kind（initial、formal、resend）、subproject_id、round_id、release_decision_ids[]、recipient_snapshot、reservation_refs[]、status、lines[]。计划行含 line_id、slot_id、goal_id、fragrance_id、formula_version_id、sample_id?、sample_form、requested_quantity、unit、dosage?、base?、document_refs[]。实寄 Shipment 保存 shipment_id、external_shipment_id、task_id、shipment_plan_id、shipped_at、tracking_or_handoff_ref、recipient_snapshot。ShipmentLine 保存 shipment_line_id、shipment_id、plan_line_id、slot_id、actual_fragrance_id、actual_formula_version_id、actual_sample_id、actual_quantity、unit、validation_status。合格正式/复寄按同目标和同约定单位累计，各自达量。初寄与回错版本均保留事实，项目实推从有效实发行投影；异常行不核销目标。
8. **状态汇总**。Slot/Goal 根据可验证回执达到自身终点。Round 可 active、waiting、completed、cancelled，只有挂该轮的当前工作已结清才完成，被新轮接续的旧方案记录替代关系。Subproject/Project 在 active、waiting、completed、cancelled 中派生，部分可推进时显示 active。重开来自新必需目标或未完成目标新计划。同步、资料缺失及部门问题记录在对应 Issue，恢复事件见主流程第 6 节。

## 4. 资产、审查和可追溯记录

- **CatalogFragrance / Tag / ExternalRef**。catalog_key、fragrance_id、source_row_ids[]、name、alias_names[]、identity_state、application_category_ids[]、category_candidates[]、tags[]（tag_id、level、category_id?）、is_new?、is_hot?、dupe_status、price_snapshot?、catalog_revision。编码冲突按 source_row 保留，人工可在 identity resolution 台账映射到唯一可执行身份。ExternalRef 具有 system、env、object_type、external_id、entity_id。FormulaVersionRef 具有 fragrance_id、formula_version_id、status（available、unavailable、unknown）、refreshed_at、namespace；仅保存配方指针。
- **ProductIdentity / ProductRelation**。Brand 具有 brand_id、标准名和别名；产品具有 product_id、brand_id、family_id?、edition_key?、names[]、identity_status、verification_ref?。关系具有 catalog_key、product_id、edition_key?、relation_status、confirmed_by?、confirmed_at?、basis_ref?。身份和关系各自确认；缺版本时仅可在评香确认接受任何已核验版本的情况下查到已确认的具体版本。
- **ExternalSample / MaterialSample**。外样有 external_sample_id、project_id、type、source_party?、external_number?、reference_product_id?、base?、received_at?、usable_for[]、status、revision；usable_for 区分感官和分析。实物样有 sample_id、fragrance_id、formula_version_id、lot?、sample_form、base?、dosage?、quantity_avail、unit、status、location?、expires_at?。
- **PriceQuote / Reservation**。报价含 quote_id、fragrance_id、formula_version_id?、amount、currency、per_unit、price_kind、as_of、valid_to?、env、source。预留有 reservation_id、shipment_plan_id、plan_line_id、sample_id、quantity、unit、expires_at、status。实时价、导入库价、发生过的用样价是三种来源。
- **SearchQuery / SearchRun / CatalogChange / TargetingFeedback**。SearchQuery 有 query_id、round_id、mode、brief_revision_id、application_category_filter、price_filter、directory_filters、positive_terms[]、negative_terms[]、hard_groups[]、unmapped[]、versions、origin、parent_query_id?。SearchRun 保存 run_id、query_id、catalog_version、price_snapshot_id、config_version、exclusions、results[]、created_at。CatalogChange 保存 catalog_key、field_path、before/after、revision、origin=manual、actor_id、reason、created_at；TargetingFeedback 保存 round_id、model_run_id?、original_query_id、new_query_id、diff、reason?、actor_id、created_at。
- **CheckSet / Requirement / Evidence / ReleaseDecision**。CheckSet 包含 check_set_id、slot_id、scope（warehouse、shipment）、fragrance_id、formula_version_id、context、rules_version、brief_revision_id、coverage_issues[]、revision。Requirement 包含 requirement_id、metric_id、subitem?、source_keys[]、owner_department?、applicability、conditions、criteria?、actual_status（unverified、pending、passed、failed、needs_review、not_applicable）、mandatory、deferral_policy、due_stage、evidence_ids[]。Evidence 包含 evidence_id、task_id?、fragrance_id、formula_version_id?、metric_id、subitem?、subject_scope、actual_conditions、method?、measured_value?、unit?、signed_verdict?、approved_by?、standard_version?、document_ref?、tested_at、valid_until?、review_status、env。ReleaseDecision 包含 decision_id、check_set_id/revision、action、verdict、blockers[]、deferred_ids[]、reason?、actor_id?、expires_at?、input_fingerprint。变更对象、要求或证据时旧结论可追溯，寄样/入库派发复核当前条件。
- **AuditEvent / Outbox / Inbox**。AuditEvent 保存 command_id、actor、origin、entity_id、revision、changed_fields、reason?、occurred_at；Outbox 保存 task_id、attempt、idempotency_key、payload_hash、delivery_status；Inbox 保存 env、source_system、event_id、payload_hash、processing_state。应用状态、审计与 outbox 同一笔事务提交。
