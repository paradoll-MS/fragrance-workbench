# 简报与故事 v3

项目简报和子项目简报均采用 project/product/scent/commercial/compliance/deliverables 六组字段。客户额外要求、开发计划、修改说明、证据及人工覆盖另外结构化保存。

界面按中文含义展示各组信息，并提供表单编辑；原始 ID 不作为气味、场景或产品信息直出。没有生成时显示明确空状态；失败时保留上版结果，不写入空简报。

故事保存完整理解摘要、按实际发生时间整理的事件、关键决定、冲突、未决、需求覆盖和来源清单。摘要的细节通过 artifact_id/locator/quote 回到原文，原文不会被摘要替代。

项目问答读取故事、各级简报、任务、人工决定和原资料，引用必须指向真实资料及原文子串。

## 2026-10-29 业务边界更正

客户三调/参考香材组合只辅助B/C，不直接映射A或主韵。A必须另有明确主体气味/主韵依据，推断记录evidence_role。customer_requirements仅限document/certificate/claim；普通气味、相容、性能、稳定性、数量、交期在普通简报中，历史原文保留于requirement_register，不作为额外证明清单。无真正额外诉求时为空。
