# Decisions ／ 业务待定

以下用来定实际业务口径。第二轮可以用试跑值完成模拟，让评香看见对应效果。

1. **初寄样允许暂缓什么、谁签字**。建议初寄样只暂缓经审批的非安全项目。香精已正式入库，无有效失败，不可暂缓项通过后，由有权限的评香或主管确认理由与承诺补齐时间。正式寄样和入库按各自完整检查项。请确认初寄白名单、角色及准许路径。模拟可先配实例；精确找香直接选库香只开放正式，仿香入库返父后可按配置初寄。
目前都允许，不需要审核，毕竟评香这边暂时还是把它当作一个推荐工具用。
2. **谁决定某款成为“精确命中”或“大牌仿香”**。建议产品存在用独立资料核验，香精关系由评香/产品负责人确认，绑定具体版本及依据。优先补经常找的产品，如 TF 白麝香、Le Labo 13/33。评香确认的关系入台账后可检索。现有候选先显示在旁边。
目前我建议你让dsh通过名称推断给可能是大牌产品的直接贴上这个大牌仿香的产品名即可，之后可以和其它标签一样直接改的。
3. **内升是否可以既有香替代并完成**。建议允许。以既有正式入库的版本过本次用途审查，确认替代对象、原因和负责人后完成内部目标。需要更换中台主推版本时由资产角色提交。
4. **混合推荐与分批**。建议允许品牌推荐同一目标组合混合选香、创香、改香，按目标位记来源。常规推荐开放选香和改香；要原创时由评香明确改为品牌路径或新增原创方向。客户未要求齐发时，可以按行完成，剩余款保留。明确必选款包含在总款数内；目标缩减应留业务确认。请确认有无默认必须齐发的项目类型。
5. **备样责任及确认边界**。建议试跑由样品/寄样组承接库存预留和不足备样，应用部门承接需要载体的试做，最终寄样由实际寄出方回凭证。请确认正式负责人和内部审批点。
不急着引入责任问题。
6. **审查规则从草案转可执行**。建议由部门负责各自指标口径和不适用审批，评香负责选择场景和确认客户额外要求。请给出首批上线市场、常见入库/寄样必检项及正式附件或签核口径。轻量版规则可先用于提示和派单，缺口由对应负责方补。
现在的部门派发返回不用很复杂，参考我对于adapter的说法。
7. **什么中台价格能用于硬筛**。试跑用正数、可比的静态库报价。正式建议读取当前可用报价与币种/单位/生效时点；未有实时价时单列旧库价，评香可选择按旧价继续探索。明确价格上限严格执行。请确认报价接口字段、税口径、按客户报价还是内部参考价，以及可接受的缓存期限。

已纳入的交互默认值包括 with_sample 可跳过检索进入开发、相似度默认留空、手工标签即时生效，以及复寄、续荐或逐方向创建承袭改香。工程侧采用带版本的快照、稳定目标位、逐条回执及同键重试。


关键补充：一个附加平台——同时承担暂时的各部门面板、数据回流看板、模拟中台的功能。各个部门的返回值可以在上面直接选择一个简单的默认bool以便于我们在测试只有评香操作主平台的时候别卡在审核；数据回流应该看到评香手动改了什么标签；模拟中台就是，我们不必去适配中台，我们去假设中台有哪些字段，然后写我们什么时候去读写；此外还有一个可以实时检查香精库和实现自定义权重的筛选排序的功能，以及查看其余字典的功能。保持UI高可读性。
