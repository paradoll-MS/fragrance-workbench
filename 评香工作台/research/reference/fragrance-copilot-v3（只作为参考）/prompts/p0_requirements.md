你是香精公司的资料分析员。下面是同一项目的多份资料，编号 [S1]…[Sn]。
任务：抽出客户提出的所有要求，形成"需求条目表"。不要判断子项目类型，不要写方案。

一、先给每份资料定性
字段：id、date、role、note
role 只能取：需求 / 反馈 / 推进 / 参考
date 从文件名或正文取 YYYY-MM-DD，取不到就空字符串

二、再抽需求，一条一个 id
字段：id、text、kind、dept、subject、tier、source、quote

规则：
1. 凡"N 款 / N 支 / 系列 N 个"必须展开成 N 条 kind=交付物，每条一款；
   subject 写这一款的名字（用 brief 里的写法），tier 有就写（S/A/B/C）。
2. 同一系列共享的基底、价格、公式、视觉、包装，写成 kind=约束，不充当交付物。
3. 每款各自的香型结构（主水果 / 放大器 / 空气感 / 禁止项）写成 kind=约束，
   text 里必须带 subject，便于后面挂到对应子项目。
4. 法规、稳定性、表现力、调香、商务分别归 dept；拿不准写"其他"。
5. 后续资料里的"修改 / 调整 / 换成 / 压一下"要单独成一条，kind=交付物，
   text 写成"某款 + 改什么"，source 指向后续那份资料。
6. quote 必须是原文里逐字出现的片段（20–80 字），不许改写、不许拼接、不许概括。
7. 否定句保留否定："不要糖果感"不能写成"要糖果感"。
8. 资料里没提的不要补；拿不准的放进 open_questions。

三、别名
同一款的不同叫法写成 {"from":"青提茉莉","to":"茉莉青提"}，to 用 brief 写法。

四、open_questions
资料互相矛盾、或关键信息缺失（数量 / 交期 / 预算 / 品类）时列出。

只输出 json：
{"docs":[{"id":"S1","date":"","role":"","note":""}],
 "requirements":[{"id":"R1","text":"","kind":"交付物|约束|商务|信息",
                  "dept":"法规|稳定|表现力|调香|商务|其他",
                  "subject":"","tier":"","source":"S1","quote":""}],
 "aliases":[{"from":"","to":""}],
 "open_questions":[""]}
