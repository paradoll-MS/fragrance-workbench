Workflow ／ 评香主流程树
读法：每个节点给出输入与展示、评香动作、写入及下一步。F 编号在 functions-函数契约.md。
业务编号采用字符串。库香、配方版本、实物样和运单是不同对象。待办只拦需要该字段的一步。

0. 建项目与接资料
├─ 新建客户项目 / 打开已有项目 → F01 open_project
│  输入名称或项目号、客户可空。显示已有资料、当前轮、实际寄样与下一步。
│  录入文字、上传或补反馈 → F02 ingest_source → Source、ParseRun、段定位。
│  浏览提取结果；资料打不开时保留原件，可补摘录、重读或用已读资料继续。
│  点「拆解需求」→ F03 propose_intents，显示每个方向、数量、交期、价格、来源和歧义。
│  点「确认拆解」→ F04 commit_intents，按独立交付目标创建子项，生成 Round 和目标位。
│  产品/方向/修改对象/需分别交付的应用不同可拆；同方向多款、多个标签或检测并入一项。
│  项目共享字段按适用范围承袭，子项具体要求优先。日期缺年或数量待定时留空，保留原话。
│  客户需求终点 shipment，内部升级终点 warehouse，派生开发终点 warehouse_return。
└─ 内部主动开发 → F01(kind=invent) + F04
   手填开发方向、应用、款数或直接列出方向。价格和交期可空；送入 3b 创香，入库完成。

0a. 老项目继续
├─ F03 读取实际寄样行、旧版需求与有效决定，按本次反馈逐条给建议。F04 按人确认落实。
├─ 新目标 → 并行子项和新轮，走 1。仅补充当前需求 → 新 BriefRevision，保留原轮。
├─ 改上一轮 → 新承袭子项，记 inherit_id、source_round_id、shipment_line_id。
│  优先最近适用的实发。唯一指向可自动关联，多个/未同步则列出待确认，禁止用参考候选充当基准。
│  保留仍适用的约束，显式标出替代的旧要求，走 1 的改香判断。
├─ 继续推荐 → 同一子项新增 Round，初始继承有效条件，排除该方向明确拒绝的编号，可手动恢复。
│  轮次与目标位绑定。点「继续推荐」时选择补足旧目标或新增交付目标，历史实寄不搬入新轮。
│  同轮的已执行决定留存，新轮条件独立。回到 1 的原推荐入口。
└─ 仅复寄 → 同子项开 resend 轮，评香确认实发样、数量、地址及仍适用条件。
   F10 plan_actions 将原香精和原版本绑定为复寄目标，走 4 正式寄样。独立记录复寄，不重复计旧目标。

1. 判型 → F05 route_requirement
├─ 有明确修改对象 → F06 resolve_reference 查询实际寄样或内部编号、版本和可用性。
│  版本可用 → modify／改香，显示原香、版本、价格、ABC、历史评香和检测；走 3c。
│  配方状态未知 → 保持改香待确认，允许填需求、查身份。配方确认不可用 → with_sample。
├─ 以实物为主要参照 → with_sample／对香，走 2a。
├─ 明确要某品牌某产品本身 → find_product／精确找香，走 2b。
├─ 需要品牌定位、人群、产品概念、风格或场景来决定香气 → recommend_brand／品牌推荐，走 2c。
├─ 按目录属性或常规气味描述推荐 → recommend_simple／常规推荐，走 2d。
└─ 关键意图歧义 → 「确认处理类型」。其他分支照常推进。创香与仿香由评香选行动触发。

2. 选香入口
├─ 2a. with_sample／对香
│  F07 save_external_sample 录入来源、类型、来源名称、到样/可用状态、已知基质。
│  相似度可空。可手选接近即可、尽量一致或自定义，简报保留原话和改进/保留项。
│  实物未到，仍可保存简报、查编号或起草开发。闻香确认及 GC 各自等可用样。
│  ├─ 「按编号查」→ F06，或「按标签找」→ F08 prepare_query → F09 rank_fragrances。
│  │  显示价格、匹配依据、实样状态；实际对香填写感官意见 → F10 plan_actions 选库香 → 4。
│  └─ 「直接开发」→ F10 保存跳过检索决定。复现进 3a，灵感原创进 3b。
│     仿香等分析样。仅作为灵感、无待核实实物承诺时，原创可以先走。
├─ 2b. find_product／精确找香
│  F06 resolve_reference → 品牌、产品、版本候选。歧义让评香选择；未核验可登记待核验。
│  「确认产品关系」→ F06 confirm_reference 按权限写身份或具体版本和来源关系，随后刷新结果。
│  F09 lookup_exact_product 仅查核验的产品与已确认关系，列出全部精确身份和另列的查询条件冲突。
│  ├─ 精确命中 → 评香选有效编号 → F10 → 4 → 正式寄样。
│  └─ 无有效命中 → 展示可核验线索及选项「核验关系」「启动仿香」「暂存」。
│     选仿香 → F10 → 3a → 4。产品目标可由评香确认后留待身份表补录，具体目标和实物仍须明确。
├─ 2c. recommend_brand／品牌推荐
│  F03 输出 BrandBrief，F08 展示定位、人群、风格、香型、理念、场景及排斥项，可改标签与硬筛。
│  F09 展示候选、总分、直命中/关联分、缺标签及价格数据状态。条件过窄显示各条件影响。
│  F10 保存选香、创香、改香的目标位，同一多款需求可混合。库香进 4，开发分别进 3b 或 3c。
└─ 2d. recommend_simple／常规推荐
   F08 展示应用品类、价格、品牌目录、仿香/新/爆及 ABC 条件，F09 出候选。
   F10 保存选香或从指定原香改香，分别进 4 或 3c。需要原创概念时，评香可明确改走品牌推荐。
   空结果允许调整、改用已知编号并记录筛选例外、暂存；精确找香仍限定在确认身份范围内。

2e. 选香里的两种编辑
├─ 「改筛选/需求标签」→ F08，保存新 SearchQuery，追加 targeting_feedback，F09 重算。
│  修改即时适用本轮。原模型输出保留，反馈供以后优化 Targeting。
└─ 「编辑香精标签」→ F11 edit_catalog_tags，保存当前香精标签及 manual 记录。
   后续选香使用新版本，已存推荐快照不变，可主动刷新当前结果。

3. 开发
├─ 3a. duplicate（dup）／仿香
│  F12 prepare_development，确认参照、实际分析样、复现方向、改进及保留项。
│  F13 dispatch_task(analysis) → 中台任务；F14 receive_result 接收样品对应的 GC 报告。
│  展示报告和异常。评香确认报告可用后进 3d；不匹配/异常可换样、补报告或重派。
├─ 3b. create／创香
│  F12 从概念和有效约束整理调香简报。确认方向、用途及记录的禁止项；数量在目标位体现。
│  可附灵感参照。确认后进 3d；无需分析任务。
├─ 3c. modify／改香
│  F06 明确基准香精与可用配方版本，F12 确认改动、保留项及原来仍有效的约束。
│  缺原版可暂存。确认无可用配方时由评香将该目标退回对香，保存原来的改动意图。
└─ 3d. 调香、验收、入库
   F13 dispatch_task(perfumery) → F14 回试作编号、配方版本、试样、调香说明；试样可后补。
   F15 evaluate_trial 等真实试样，评香对照目标，退回时备注并新增内部迭代，客户 Round 保持。
   通过时锁定试作与配方版本 → 4 入库审查；过审后 F13 派仓库。
   F14 收正式入库回执 → F16 accept_warehouse 写正式编号、配方版本、入库凭证。
   ├─ 有父项 → 按 parent_round_id + slot_id 回流，客户父项使用自身条件走 4 二查。
   ├─ 客户直接改香 → 同目标切到 4 二查，版本沿用正式入库回执。
   └─ 内部项目 → 入库完成；内部升级选既有库香时做 4 入库用途审查，再走 F16 替代确认。

4. 检查与放行
├─ 每款每版本独立 F17 build_checks(source、审查品类、目标市场、用途/基质/添加量、默认和客户要求)。
│  显示适用规则、客户要求、缺项、已核销/不适用依据。应用品类进入选香，审查品类决定检查。
│  未知地区/用途先生成可确定的清单。规则适用性未确认时，记录待审查，放行前补齐。
├─ F18 match_evidence 用同香精版本、对象、测试方法/条件、市场、剂量及有效期核对。
│  已有符合凭证自动关联；检查条件不匹配、附件只有历史引用、标准未知则保留待核销。
├─ 「派发检查」→ F19 plan_checks + F13 分部门发已具备条件的事项。
│  合规、质量、应用各自提交实际条件、结论和凭证 → F14 + F18。部分回执逐条核销。
│  已知失败标在对应香精。评香可补充检测、换香或改配方。单条待办可恢复，其他款继续。
├─ F20 decide_release 按每个目标位、配方版本及动作判定。
│  入库/正式寄样：范围已确认、强制条目通过、其余有效要求通过或有授权的适用性结论。
│  初寄样：路径允许、已正式入库、不可暂缓项全过、无已知有效失败；待办仅可按批准策略暂缓。
│  初寄确认记录说明、责任人、后续待办和截止时间。仍用当前证据重新判定。
└─ 入库放行回 3d。对外放行进 5。find_product 库内精确命中只开放正式寄样。

5. 样品与实际寄样
├─ 「准备样品」→ F21 prepare_shipment。允许先备样；寄出时核查门禁、库状态与版本。
│  输入每款寄量、单位、样品形态、基质/用量（需要时）、地址、随附文件。
│  中台查库存并原子预留；不足则 F13 派打样。F14 回样品号、版本、数量和可用状态，重新预留。
├─ 「派发寄样」→ F22 dispatch_shipment 复核门禁和预留，锁定寄样清单，发送寄样任务。
│  F14 回实际 ShipmentLine、实寄数量、运单或交接凭证。回错版本视为异常；部分回执保留实发。
├─ F23 apply_shipment 写入实发记录与可继续处理的余量。
│  初寄记录实发但保留正式交付任务。正式寄样只计实际寄出的合格目标，部分实寄继续剩余目标。
└─ F24 refresh_progress 按目标位及终点汇总，客户后续反馈返回 0a。

6. 暂存与恢复贯穿所有步骤 → F24 refresh_progress
├─ 展示当前可操作项、独立等待原因、负责人和交期。只有实际依赖成为阻断项。
├─ 各节点用同一张 WorkflowIssue 存等待原因，分别以对象 ID 接收恢复事件。
│  brief_incomplete → brief_confirmed → 从当前判型或确认节点继续；空价格、交期或相似度本身无需挂起。
│  reference_unresolved / formula_unknown → reference_confirmed / formula_ref_updated → 复核身份、对象和版本。
│  sample_unavailable → sample_changed → 根据可用用途开放闻香确认或分析派发。
│  gc_pending / trial_pending → task_result_accepted → 等 GC 人工确认，或等试样后开放评香。
│  check_context_missing / check_pending → brief_confirmed / check_evidence_changed → 只重算受影响条目。
│  check_failed → 评香选择复测、换香或改方 → 新任务尝试或新方案，原失败记录保留。
│  warehouse_pending → warehouse_accepted → 回开发原目标位或进入客户二查。
│  stock_short / reservation_expired → sample_available / reservation_updated → 复查余量与可派发批次。
│  shipment_pending → shipment_applied → 核算实发和余额，下一批仍有独立动作。
├─ 无法确认任务是否已执行时先查状态，再用同键重试。已执行快照和错误回执可追溯。
└─ 项目以必需目标的完成、正式缩减或项目取消结束。历史完成后可因新增必需目标重新激活。
