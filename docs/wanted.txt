项目工作流 Project Workflow
│
├─ 0. 项目入口
│   │
│   ├─ 对象：Project
│   ├─ 输入：客户需求原文 / 客户反馈 / 双马内部开发需求
│   ├─ 展示：原始需求、项目历史、关联样品、历史实推记录
│   │
│   ├─ 判断：是否为用户手动发起的主动产品开发？
│   │   ├─ 是
│   │   │   └─ invent
│   │   │       ├─ 创建内部项目
│   │   │       ├─ 确认开发方向、品类、价格、开发数量
│   │   │       ├─ final_endpoint = warehouse
│   │   │       └─ 直接创建 create 子项目 → 执行 [F02]
│   │   │
│   │   └─ 否
│   │       └─ 判断：是否关联已有项目？
│   │           │
│   │           ├─ 否 → create_project()
│   │           │       └─ 进入 1. 需求拆分
│   │           │
│   │           └─ 是 → get_project_context()
│   │                   └─ 对本次反馈进行逐条意图判断
│   │                       │
│   │                       ├─ 是否新增独立需求？
│   │                       │   └─ 是 → 创建并行 Subproject
│   │                       │           → 进入 1. 需求拆分
│   │                       │
│   │                       ├─ 是否针对某款已推香精提出修改？
│   │                       │   └─ 是 → 创建 inherit 子项目
│   │                       │       ├─ 默认检索父项最近一次实推
│   │                       │       ├─ 展示历史实发香精及客户反馈
│   │                       │       ├─ 唯一指向 → 自动关联
│   │                       │       ├─ 多个可能对象 → 评香确认
│   │                       │       ├─ 承袭原品类、地区、客户要求
│   │                       │       ├─ 提取本次新增/改变的要求
│   │                       │       └─ 进入 2. 需求判型
│   │                       │
│   │                       ├─ 是否仍为原需求，只需继续推荐？
│   │                       │   └─ 是 → 原 Subproject 新增 Round
│   │                       │       ├─ 保留历次推荐及实推记录
│   │                       │       ├─ 更新本轮需求及筛选条件
│   │                       │       ├─ 标记此前已拒绝的香精
│   │                       │       └─ 返回原类型的检索/选香入口
│   │                       │
│   │                       ├─ 是否仅要求复寄已推香精？
│   │                       │   └─ 是 → 确认原实发香精及数量
│   │                       │           → 执行 [F04] 客户交付检查
│   │                       │
│   │                       └─ 无法明确判断 → 评香手动归属
│   │
│   └─ 输出：project_id、原始输入记录、项目上下文
│
│
├─ 1. 需求拆分 及 公共信息提取
│   │
│   ├─ 调用：extract_intents(brief, project_context)
│   │
│   ├─ 判断：是否存在多个独立交付目标？
│   │   ├─ 是 → 拆分为多个并行 Subproject
│   │   └─ 否 → 创建单个 Subproject
│   │
│   ├─ 拆分依据
│   │   ├─ 不同目标产品
│   │   ├─ 不同应用品类且需要分别提供方案
│   │   ├─ 不同参照样品且需要分别对香
│   │   ├─ 不同品牌/香气概念且分别要求交付
│   │   └─ 不同修改对象或独立开发目标
│   │
│   ├─ 不拆分的情况
│   │   ├─ 同一目标要求推荐多款香精
│   │   ├─ 同一目标存在多个描述性标签
│   │   └─ 同一香精存在多个检测或改进要求
│   │
│   ├─ 每个 Subproject 提取公共字段  yy
│   │   ├─ brief_original：对应客户需求原文
│   │   ├─ internal_category_id：内部品类
│   │   ├─ target_region：目标地区
│   │   ├─ price_range：价格区间
│   │   ├─ price_filter_enabled：价格硬筛开关  xx
│   │   ├─ requested_count：目标香精款数
│   │   ├─ delivery_deadline：交期
│   │   ├─ customer_requirements[]：客户额外要求
│   │   ├─ parent_id：调用该任务的父项，可为空
│   │   ├─ inherit_id：承袭的历史子项，可为空
│   │   └─ source_round_id：关联历史轮次，可为空
│   │
│   ├─ 判断最终终点 final_endpoint
│   │   ├─ 双马内部香精升级 → warehouse
│   │   ├─ 主动产品开发 → warehouse
│   │   ├─ 客户需求 → shipment
│   │   └─ 派生开发子项 → warehouse + return_to_parent
│   │
│   ├─ 评香确认：拆分结果、公共字段、最终终点
│   ├─ 调用：confirm_subprojects()
│   └─ 对每一个已确认的 Subproject 独立执行 2
│
│
├─ 2. 子项目判型与完整执行路径
│   │
│   ├─ Q1：是否要求修改/升级某个特定的已有香精？
│   │   │
│   │   ├─ 是
│   │   │   └─ Q1.1：是否存在可调用的内部配方？
│   │   │       │
│   │   │       ├─ 是 → 5. modify
│   │   │       │   │
│   │   │       │   ├─ 对象：ModifyBrief
│   │   │       │   ├─ 前提
│   │   │       │   │   ├─ 已确认被改香精的内部编号
│   │   │       │   │   ├─ 已确认原配方版本
│   │   │       │   │   └─ 已明确改动要求
│   │   │       │   │
│   │   │       │   ├─ 调用：resolve_base_fragrance()
│   │   │       │   │   ├─ 客户指定内部编号 → 按编号查询
│   │   │       │   │   └─ 客户指定前轮实发样 → 查询 Shipment
│   │   │       │   │
│   │   │       │   ├─ 展示 yy
│   │   │       │   │   ├─ 原香精属性、价格、ABC 标签
│   │   │       │   │   ├─ 原配方版本标识
│   │   │       │   │   ├─ 历史评香记录
│   │   │       │   │   ├─ 本次客户改动要求
│   │   │       │   │   └─ 原有要求及检测凭证
│   │   │       │   │
│   │   │       │   ├─ 评香确认 yy
│   │   │       │   │   ├─ base_fragrance_id
│   │   │       │   │   ├─ base_formula_version_id
│   │   │       │   │   ├─ changes[]：需要改变的属性
│   │   │       │   │   ├─ retained[]：需要保留的属性
│   │   │       │   │   └─ requirements[]：承袭及新增约束
│   │   │       │   │
│   │   │       │   ├─ 前提是否全部满足？
│   │   │       │   │   ├─ 否 → [F06] 暂存及恢复
│   │   │       │   │   └─ 是 → confirm_modification_brief()
│   │   │       │   │
│   │   │       │   ├─ 以已有配方为起点
│   │   │       │   ├─ 执行 [F03]
│   │   │       │   │   └─ 调香 → 评香验收 → 检查 → 入库
│   │   │       │   │
│   │   │       │   └─ 入库成功后的去向
│   │   │       │       ├─ 存在父项 → 返回父项新香精编号
│   │   │       │       ├─ 双马内部升级 → 本子项目完成
│   │   │       │       └─ 客户改香需求
│   │   │       │           └─ [F04] 客户要求二查
│   │   │       │               └─ [F05] 初寄样/寄样
│   │   │       │
│   │   │       ├─ 否，确认没有可用配方
│   │   │       │   └─ 转入下方 2. with_sample
│   │   │       │
│   │   │       └─ 尚不能确定配方是否存在
│   │   │           └─ [F06] 等待原香精身份/配方确认
│   │   │
│   │   └─ 否 → Q2
│   │
│   │
│   ├─ Q2：是否以客户实物样品作为主要评价参照？
│   │       或者是否为无可用配方的香精升级？
│   │   │
│   │   ├─ 是 → 2. with_sample
│   │   │   │
│   │   │   ├─ 对象：SampleBrief + ExternalSample
│   │   │   ├─ 前提
│   │   │   │   ├─ external_samples 中存在样品登记
│   │   │   │   ├─ 相似度要求已明确 xx
│   │   │   │   └─ 改进要求已明确（无改进要求可为空）
│   │   │   │
│   │   │   ├─ 是否已有样品登记？
│   │   │   │   ├─ 否 → register_external_sample()
│   │   │   │   └─ 是 → 关联 external_sample_id
│   │   │   │
│   │   │   ├─ 展示及确认
│   │   │   │   ├─ 样品来源、编号、类型、到达状态
│   │   │   │   ├─ 原产品及实际应用基质
│   │   │   │   ├─ 相似度目标
│   │   │   │   ├─ 需要改进的属性
│   │   │   │   └─ 需要保留的属性
│   │   │   │
│   │   │   ├─ 样品是否已到达且可用于对香？
│   │   │   │   ├─ 否 → [F06] waiting_sample
│   │   │   │   │       └─ sample_arrived 事件触发恢复
│   │   │   │   └─ 是 → 开放评香对香面板
│   │   │   │
│   │   │   ├─ 评香决定如何查找候选香精  xx(选择跳过查找则直接到派发B)
│   │   │   │   │
│   │   │   │   ├─ 已知可能匹配的内部香精
│   │   │   │   │   └─ 按内部编号查询并闻香比对
│   │   │   │   │
│   │   │   │   └─ 需要借助标签缩小候选范围
│   │   │   │       ├─ 评香输入关键词，如清新、百香果
│   │   │   │       ├─ extract_abc_query(keywords)
│   │   │   │       ├─ 按内部品类筛选候选池
│   │   │   │       ├─ 价格等条件按已确认需求启用
│   │   │   │       ├─ 调用 [F00] ABC 匹配与排序
│   │   │   │       └─ 展示候选编号、标签、价格、分数
│   │   │   │
│   │   │   ├─ 评香闻香、对香及人工判断
│   │   │   │   ├─ 实际香气相似程度
│   │   │   │   ├─ 是否满足客户改进方向
│   │   │   │   └─ 是否存在可以接受的库内香精
│   │   │   │
│   │   │   └─ 判断：是否能够从库内直接选香？
│   │   │       │
│   │   │       ├─ 是 → 派发 A
│   │   │       │   ├─ confirm_selection(fragrance_ids)
│   │   │       │   ├─ [F04] 法规＋稳＋表
│   │   │       │   └─ [F05] 初寄样/寄样
│   │   │       │       └─ 若为内部升级，则按入库终点判断；
│   │   │       │          已入库原香替代升级的认定规则待确认
│   │   │       │
│   │   │       └─ 否 → 派发 B
│   │   │           └─ 评香是否确认启动开发？
│   │   │               ├─ 否 → 继续对香或 [F06] 暂存
│   │   │               └─ 是
│   │   │                   └─ 判断开发目标
│   │   │                       ├─ 复现或接近参照样品
│   │   │                       │   └─ 派生 duplicate → [F01]
│   │   │                       └─ 以样品为灵感重新原创
│   │   │                           └─ 派生 create → [F02]
│   │   │
│   │   │               开发子项执行并返回：
│   │   │               ├─ 分析（duplicate）/ 概念 brief（create）
│   │   │               ├─ 调香
│   │   │               ├─ 评香验收
│   │   │               ├─ 法规＋稳＋表：入库检查
│   │   │               ├─ 正式入库
│   │   │               ├─ 返回新香精编号至 with_sample
│   │   │               └─ 判断父项最终终点
│   │   │                   ├─ warehouse → 完成内部升级
│   │   │                   └─ shipment
│   │   │                       ├─ [F04] 客户要求二查
│   │   │                       └─ [F05] 初寄样/寄样
│   │   │
│   │   └─ 否 → Q3
│   │
│   │
│   ├─ Q3：客户是否确切要求某个品牌下的某款产品？
│   │       要求的是该产品本身，而非借用其品牌气质？
│   │   │
│   │   ├─ 是 → 1. find_product
│   │   │   │
│   │   │   ├─ 对象：ProductIdentity
│   │   │   ├─ 前提：明确且可识别的目标产品
│   │   │   ├─ 提取：品牌名称 + 产品名称 + 版本（如有）
│   │   │   │
│   │   │   ├─ 调用：resolve_product_identity()
│   │   │   │   ├─ 查询已通过联网批量搜索建立的产品身份表
│   │   │   │   ├─ 品牌别名归一化
│   │   │   │   ├─ 产品名称及别名归一化
│   │   │   │   └─ 获取标准 product_id
│   │   │   │
│   │   │   ├─ 产品身份是否能够唯一确定？
│   │   │   │   ├─ 否 → 展示可能的产品身份
│   │   │   │   │       ├─ 评香确认 → 继续
│   │   │   │   │       └─ 无法确认 → [F06] 暂存
│   │   │   │   └─ 是 → 继续
│   │   │   │
│   │   │   ├─ 调用：search_exact_product(product_id)
│   │   │   │   ├─ 查询香精与目标产品的身份关联记录
│   │   │   │   ├─ 仅允许身份精确匹配
│   │   │   │   └─ 不进行 ABC 评分或香型相似检索
│   │   │   │
│   │   │   └─ 判断：是否命中库内香精？
│   │   │       │
│   │   │       ├─ 是 → 派发 A
│   │   │       │   ├─ 展示全部精确命中的内部香精
│   │   │       │   ├─ 展示编号、价格、品类、已有检测记录
│   │   │       │   ├─ 评香在命中范围内选择
│   │   │       │   ├─ confirm_selection(fragrance_ids)
│   │   │       │   ├─ [F04] 法规＋稳＋表
│   │   │       │   └─ [F05] 正式寄样
│   │   │       │       └─ 此路径不开放初寄样
│   │   │       │
│   │   │       └─ 否 → 派发 B
│   │   │           ├─ 展示无精确命中结果
│   │   │           ├─ 评香确认是否启动仿香
│   │   │           │   ├─ 否 → [F06] 暂存
│   │   │           │   └─ 是 → spawn_subproject(duplicate)
│   │   │           ├─ 执行 [F01]
│   │   │           │   ├─ 确认目标产品及分析样品
│   │   │           │   ├─ 派发分析 → GC 报告
│   │   │           │   ├─ 派发调香
│   │   │           │   ├─ 评香验收
│   │   │           │   ├─ 法规＋稳＋表：入库检查
│   │   │           │   └─ 入库
│   │   │           ├─ 返回新香精编号至 find_product
│   │   │           ├─ [F04] 法规＋稳＋表：客户要求二查
│   │   │           └─ [F05] 初寄样/寄样
│   │   │
│   │   └─ 否 → Q4
│   │
│   │
│   ├─ Q4：是否需要理解品牌定位、人群、理念、
│   │       风格、场景或原创产品概念才能完成选香？
│   │   │
│   │   ├─ 是 → 4. recommend_brand
│   │   │   │
│   │   │   ├─ 对象：BrandBrief + SearchQuery
│   │   │   ├─ 前提
│   │   │   │   ├─ 内部品类
│   │   │   │   ├─ 价格范围或明确关闭价格筛选
│   │   │   │   └─ 可用于语义理解的客户 brief
│   │   │   │
│   │   │   ├─ 调用：extract_brand_brief()
│   │   │   │   ├─ positioning：定位
│   │   │   │   ├─ audience：人群
│   │   │   │   ├─ style：风格
│   │   │   │   ├─ olfactory：香型
│   │   │   │   ├─ context：语境
│   │   │   │   ├─ concept：理念
│   │   │   │   ├─ scenario：场景
│   │   │   │   └─ negative_attributes：排斥属性
│   │   │   │
│   │   │   ├─ 调用：generate_abc_query(BrandBrief)
│   │   │   │   ├─ 映射至已有 A/B/C 标签字典
│   │   │   │   ├─ 提取各维度的目标标签
│   │   │   │   ├─ 保留对应的客户原文
│   │   │   │   └─ 区分硬性限制与匹配偏好
│   │   │   │
│   │   │   ├─ 展示语义理解及筛选面板
│   │   │   │   ├─ 品牌 brief 解析
│   │   │   │   ├─ ABC 目标标签
│   │   │   │   ├─ 内部品类（必选）
│   │   │   │   ├─ 价格范围（可关闭）
│   │   │   │   ├─ 品牌目录（可选）
│   │   │   │   ├─ 新品/爆品/大牌仿香
│   │   │   │   └─ 评香可以调整上述条件
│   │   │   │

└─ 3. 项目完成状态判断
    │
    ├─ 每次子项目发生状态变化时触发
    ├─ 调用：evaluate_project_completion(project_id)
    │
    ├─ 逐个检查 Subproject.final_endpoint
    │   ├─ warehouse
    │   │   └─ 是否已确认正式入库？
    │   ├─ shipment
    │   │   └─ 是否已完成全部正式寄样目标？
    │   └─ warehouse + return_to_parent
    │       └─ 是否已正式入库且成果已返回父项？
    │
    ├─ 以下情况均不能标记为最终完成
    │   ├─ 仅完成选香
    │   ├─ 仅完成 GC 分析
    │   ├─ 仅完成调香
    │   ├─ 仅通过评香验收
    │   ├─ 仅完成部分检测
    │   ├─ 客户需求仅完成开发子项入库
    │   └─ 客户需求仅完成初寄样
    │
    ├─ 所有必要子项是否达到各自最终终点？
    │   ├─ 否 → Project.active
    │   │       └─ 保持各子项独立推进及等待状态
    │   └─ 是 → Project.completed
    │
    └─ 收到后续客户反馈
