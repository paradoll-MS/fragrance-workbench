# 推荐与打分（v2）

更新：2026-10-28  
原则：**先硬筛（不含 C），再计分；C 和 AB 都只是加分项。**

## 1. 所有推荐共用的硬门槛

1. 子项目必须有 `category_l3`、`norm_class`、`new_class`。
2. 候选香精的 `new_class` 必须与子项目相同。
3. 价格：候选价格 ≤ `target_price × (1 + t%)`，默认 `t=20`。  
   - 客户给区间 → 用区间上限作为 target；  
   - 无 target → 不做价格硬筛，但结果标“价格未知”；  
   - 只放宽上限，不设下限。
4. 香型：
   - 子项目有明确 **A1**：**默认硬筛**，候选命中任意一个 A1 即通过（OR）；条件区可取消勾选“A1 硬筛”，取消后按 A2/A3 宽筛；
   - 没有 A1、但有明确 A2/A3：候选命中任意一个 A2/A3 即通过（OR，宽筛）；
   - A1 与 A2/A3 同时存在：A1 勾选时以 A1 为准，A2/A3 只用于解释/排序；取消 A1 硬筛后按 A2/A3 宽筛。
5. 品牌/产品：
   - `find_product`：精确品牌+产品+版本；
   - `recommend_simple`：可品牌级过滤，不锁具体产品；
   - `recommend_brand`：不按大牌仿香过滤。
6. 状态：淘汰/停用/不可用配方不进候选。

## 2. 六类任务各自的推荐逻辑

### 2.1 find_product 找一个香

- 输入：品牌+产品+版本。
- 先查 `brand_product_labels` / `market_product_profiles` 的精确身份。
- **有**：返回匹配内部号，按中央库/价格/版本排序；不计算 C/AB 分。
- **无**：子项目转 `create`（仿香/创香），保留目标产品作为参考；不硬推近似款冒充同款。

### 2.2 match_sample 对一个香味

- 客户寄来外部样品，评香先登记收样。
- 评香自己输入/按 A1/A2/A3/C 标签检索，确定若干内部号。
- 系统只做检索与记录，不自动给“像不像”的结论。
- 可以就推；不行转 `create`/`modify`。

### 2.3 recommend_simple 推荐香·简单厂家

- 硬筛：新类 + 价格 + A1/A2/A3 + 品牌（可选）。
- **不使用 C/AB 计分**。
- 默认展示顺序：价格升序 → 爆品/中央库（展示用）→ 编号；评香可改排序。
- 表现力要求只展示客户原文，不作为筛选条件。

### 2.4 recommend_brand 推荐香·品牌客户/创香前

- C 是什么：C 是**商业定位分类**（如“家庭氛围 / 酒店空间 / 大众洗护”），不是香精编号，也不是自由文本标签；`C_xxx` 只是内部 id，界面优先显示中文标签/路径。
- 硬筛：新类 + 价格 + A1/A2/A3（如有）+ 品牌（如有）。
- **C 不是硬筛**：C 只用于计分。目标 C 为空时仍可推荐，C 分为 0；有目标 C 时，按类型/口径命中，每个 +3。不要求候选的每一条 C 归属都相同。
- 一个子项目可以有多个目标 C；LLM/评香认为符合的都可以保留。候选命中任意一个目标 C 口径即可，不要求候选的每条 C 归属都与目标完全一致。
- 推荐表显示候选自己的 C 归属，不是把目标 C 强行套到候选上。
- **C 计分**：每个命中的目标 C **+3 分**；一个子项目多个目标 C 可累计；C 分不封顶。
- **AB 计分**：
  - 取所有目标 C 的固定 `ab_ids` 并集；
  - 与候选香精的 A/B 标签取交集；
  - 每个 distinct 标签 +1；
  - `total_score = C命中数 × 3 + AB命中数 × 1`。
- 排序：`total_score` 降序 → C 分降序 → AB 分降序 → 价格差升序 → 爆品/中央库（展示）→ 编号。
- 推荐表同时显示候选自己的 C 归属、C 分、AB 分、总分；没有 AB 命中也可展示，但必须让评香看到“C 命中几个、AB 0”。

### 2.5 modify 改香

- 锁定一个内部号/版本；不跑推荐。
- 记录改动目标：基质、味道、价格、表现力、法规等。
- 交调香；可生成 T05/调香任务。

### 2.6 create 创香

- 不跑推荐；把调香师需要的信息 + 评香参考香（含备注）交给调香。
- 参考香可以没有；可以是市场产品/内部号/口头描述。

## 3. 子项目拆分规则

1. 每个**精确产品**（品牌+产品+版本）单独成 `find_product`。
2. 只到品牌、没有精确产品 → 一个 `recommend_simple`。
3. 品牌 + 多个指定产品：
   - 每个指定产品一个 `find_product`；
   - 剩余“该品牌其它香”一个 `recommend_simple`；
   - 例：“Le Labo 的香，33 和 13 一定要有” → 3 个子项目：33、13、其它 Le Labo。
4. 只指定 33 → 一个 `find_product`。
5. 只指定 Le Labo → 一个 `recommend_simple`。
6. 客户寄样 → 一个 `match_sample`。
7. 锁定旧号改香 → 一个 `modify`。
8. 从零创作 → 一个 `create`。
9. 一个子项目只有一个主类型；类型可升级并保留历史。

## 4. C 的口径

- **C 不是硬筛**：C 只用于加分；目标 C 为空仍可跑推荐。
- 有目标 C 时，按类型/口径命中：选父类时子类同属；候选可有多条 C 归属，一条命中即可。
- 一个品牌推荐子项目可以有**多个目标 C**；每个命中目标 C +3，多个可累计。
- 目标 C 为空 → C 分为 0，候选仍来自新类/价格/A1A2A3 硬筛。
- 不使用“所有 C 归属必须相同”的旧逻辑。

## 5. AB 的口径

- 只使用目标 C 的固定 `ab_ids`。
- 与香精主标签中的 A/B 取交集。
- 每个 distinct A/B 标签 +1；同一标签多次出现只算一次。
- AB 分只用于 `recommend_brand`；简单推荐不计分。
- 不把 C 的父节点、兄弟 C 的 AB 混进来。

## 6. 示例

### 示例 A：Le Labo 33 + 13 + 其它

客户原话：“我要 Le Labo 的香，其中 33 和 13 一定要有。”

拆为：

1. `find_product`：Le Labo Santal 33；
2. `find_product`：Le Labo Another 13；
3. `recommend_simple`：Le Labo 品牌下其它香（排除 33/13）。

### 示例 B：品牌客户酒店大堂

- 新类：空间香氛；
- 目标 C：`酒店与公共空间/大堂`（可多个同类 C）；
- 硬筛：价格 ≤ 300×1.2=360；A1 若有则 OR；
- 候选命中目标 C 的类型/口径即可，不要求所有 C 归属相同；
- 目标 C 的固定 AB：`温暖感、木质调、空间感`；
- 例：候选命中 1 个目标 C（+3）、AB 命中 2 个（+2）→ 总分 5；AB 3 个 → 总分 6。

### 示例 C：简单厂家“桃子味，200以内”

- 新类：按产品定；
- A1：桃子（明确）→ 命中桃子即通过；
- 价格 ≤ 240；
- 无 C/AB 分；按价格升序展示，爆品/中央库只做标记。

## 7. 结果解释必须写

每条候选至少给：

- 硬筛通过项；
- 目标 C（品牌推荐）；
- 命中的 AB / 未命中；
- 价格与目标差；
- 爆品/新品/大牌仿香标签（只展示，不改变分数）；
- 风险：法规/稳定性/表现力缺项。

## 8. 可调面板

- 价格上限（默认 +20%，可改）；
- 品牌/产品过滤；
- A1/A2/A3 选择；
- 目标 C（只能一个）；
- 排序：AB 分 / 价格 / 爆品；
- 短名单/淘汰。

算法版本写入结果；同输入同版本可复现。
